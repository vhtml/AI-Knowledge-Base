# notes_check · 教程笔记结构校验

**重点在一件事上：这套教程是手工维护的长文档，最容易坏在结构上，而结构坏了肉眼看不出来。**

被校验的笔记在 [`AI/AI-Product/`](../../../AI/AI-Product/)，
工具在 [`notes_check.py`](notes_check.py)。

---

## 快速开始

**必须在 `Demos/examples` 目录下运行**（包在 `examples` 下，Python 靠当前目录找包）：

```bash
cd Demos/examples

# 校验笔记结构
uv run --project .. python -m notes_check
```

工具只用标准库，裸解释器也能跑：

```bash
cd Demos/examples && python3 -m notes_check
```

退出码 0 = 全部通过，1 = 有检查项失败。

## 检查什么

| 检查项 | 验证内容 |
| --- | --- |
| 文件齐全 | 十六章 + 四份附录 + 索引都在 |
| 章节结构 | 每章首行是 `# NN · 标题`，且有「这篇要回答 / 本章练习 / 本章要点 / 一句话结论」四件结构件 |
| 代码围栏 | 围栏成对——**没闭合会让后面整段被当成代码渲染** |
| 相对链接 | 所有相对链接都指向真实存在的文件（含 `%20` 编码解码） |
| 索引覆盖 | README 把十六章和四份附录都列进去了 |
| 无占位符 | 不残留 TODO / 待补 / 待填 / FIXME |
| 表格完整性 | 每张表列数一致、第二行是合法分隔行 |

---

## 为什么值得留一个工具

这三个 bug 都是靠这个校验器抓出来的，肉眼通读 6000 行是发现不了的：

1. **代码围栏未闭合**——某一章的围栏少了一个，后面的 bash 命令块整段被吞进代码块，
   渲染出来是一坨。
2. **链接目标用了字面空格**——`(03-场景筛选：什么该用 AI、什么不该.md)` 在
   CommonMark 里会被截断，链接指向一个不存在的路径。
3. **表格列数错位**——某张表多了一列，后面的列全部串位。

它还有一个附加价值：**给"笔记和实验口径是否分叉"提供自动检查**。
教程里多处引用了具体口径（AI Fit 的权重与阈值、优先级公式），
口径改了但别处没改时，这里会报出来。

## 怎么扩展

检查项是一个 `CHECKS` 元组，每个检查函数返回 `Report`（`name` + `problems`）：

```python
def check_你的检查项() -> Report:
    report = Report("检查项名字")
    ...
    return report
```

把函数加进 `CHECKS` 即可。新增章节时，同步更新 `CHAPTER_FILES`；
新增附录时，更新 `APPENDIX_FILES`。
