# vibe_film_lab · Vibe 知识动画教程实验

**重点在两件事上：一条知识短片的内容设计（形象、事实、分镜）和一条代码渲染管线（纯函数、逐帧、导出）。**

配套原理笔记在 [`AI/Knowledge-Film/`](../../../../AI/Knowledge-Film/)，一章一个主题、一篇笔记。
十二章笔记里，**六章配了可执行实验**——实验查的对象是**毕业作品自己**
（`capstone/fourier_C/` 里的真片），不是样例数据：查样例只能证明检查器能跑，
查真片才能证明片子没问题。

没有实验的那六章（片型解剖、形象优先、文案体检、两套外观、声音、工具选型）
是纯判断标准，留在笔记里就够——它们不需要跑起来才有意义。

所有实验**离线运行**：不联网、不消耗 token、不调用模型。跑挂了就是没学会。

渲染相关的实验需要本机装了 **ego lite** 和 **ffmpeg**；
没装的话那几章会打印"跳过"并继续，不会中断整轮。

## 快速开始

**必须在 `Demos/examples` 目录下运行**（包在 `examples` 下，Python 靠当前目录找包）：

```bash
cd Demos/examples

# 跑某一章
uv run --project .. python -m vibe_film_lab ch07

# 跑全部 6 章实验
uv run --project .. python -m vibe_film_lab all

# 列出各章主题
uv run --project .. python -m vibe_film_lab list

# 自检（不依赖 pytest）
uv run --project .. python -m vibe_film_lab.selftest
```

除渲染那几章外，实验只用标准库，裸解释器也能跑：

```bash
cd Demos/examples && python3 -m vibe_film_lab all
```

## 目录结构

```
vibe_film_lab/
├── __init__.py          包入口
├── __main__.py          命令行入口（ch03/ch05/ch07/ch08/ch10/ch11 / all / list / selftest）
├── labkit.py            公共口径层：分镜表解析、事实核对、字幕时间轴、门槛检查
├── selftest.py          自检（10 项）
├── lessons/             六章实验，每章一个模块，断言写在代码里
├── engine/
│   ├── template.html    渲染页模板：把 URL 上的 t 交给 seek(t)
│   └── render.py        逐帧渲染 + ffmpeg 编码 + sheet/stills/motion/det
└── capstone/
    └── fourier_C/       毕业作品：一条 30 秒的完整短片
        ├── storyboard.md 分镜表 + 事实表 + 时间轴（唯一真相）
        ├── index.html
        ├── film.js      全部画面（字幕、七个场景、片名卡、渲染引擎）
        └── README.md    怎么跑
```

**没有 `fixtures/`。** 样例数据曾经用来给体检器当输入——那只能证明检查器
能跑，证明不了片子没问题。现在检查器的输入只有一份：`capstone/fourier_C/storyboard.md`，
它就是**唯一真相**。

## 唯一真相：分镜表 ↔ 代码

`capstone/fourier_C/storyboard.md` 里有四张表：事实表、分镜表、时间轴、片尾文献。

`film.js` 是它的实现，必须和它**逐字一致**：

- 字幕文本逐字相同；
- 起始时间和停留时间和时间轴表一致；
- 第 3、5、7 章会把这两边当面对一遍，不一致当场报错。

所以改文案的顺序永远是：**先改 `storyboard.md`，再改 `film.js`，最后跑 `ch07` 和 `ch11`**。
反过来改——先改代码后补表——迟早有一句字幕对不上。

## 几个可以自己动手改的地方

**改 `film.js` 里的 `SUBS`，再跑 `ch07` 和 `ch11`。**
两章都会报"字幕和分镜表不一致"——这就是"分镜表是唯一真相"的强制手段。

**改 `storyboard.md` 的分镜表，再跑 `ch05`。**
体检器会指出新镜是不是缺三问、是不是和前一镜撞了画法、「不画」占比还合不合理。

**把 `film.js` 里的 `seeded()` 换成 `Math.random()`，再跑 `ch07`。**
静态检查会当场抓住你；就算躲过静态检查，`--det` 也会因为两帧不一致而失败。

## 自检覆盖什么

| 检查项 | 验证内容 |
| --- | --- |
| lesson 可导入 | 六个模块都在，都导出 `run()` |
| 成片分镜表 | 四张表齐全；8 镜 5 事实 8 行时间轴；自身过体检 |
| 染色标记解析 | 标记只染前一段；写错的颜色词不被吞掉 |
| 时间轴口径 | 单调、不重叠、停留时长被钳制 |
| 分镜体检器 | 坏分镜表抓得住 |
| 事实双向核对 | 正反两个方向都能报出问题 |
| 引擎文件 | 文件齐全；film.js 里没有不确定性来源 |
| film.js 与分镜表一致 | 字幕逐字一致、起始与停留时间一致、场景铺满全片 |
| 端到端渲染 | 渲帧 → 编码 → ffprobe 校验分辨率/帧率 |
| 渲染脚本入口 | `--det` 命令行跑得通 |

## 渲染用的浏览器

渲染走 **ego lite**（`ego-browser` CLI 驱动），不依赖系统里装没装 Chrome。
视口用 CDP 的 `Emulation.setDeviceMetricsOverride` 钉死成目标分辨率，
所以截出来的帧就是 1920×1080，和浏览器窗口多大无关。
