# kb-note-writer

把一次技术实践沉淀成本仓库的知识笔记。产出的笔记要能被半年后的自己直接用起来——
所以笔记里写的是**判断依据**，不是操作步骤的复读。

## 流程

1. 判断这批经验落在哪个分类目录（分类表见 [references/repo-conventions.md](references/repo-conventions.md)）
2. 判断笔记形态：单篇笔记 / 索引页 / 补充已有笔记（模板见 [references/note-templates.md](references/note-templates.md)）
3. 按模板起草，起草时用 [assets/note-template.md](assets/note-template.md) 做骨架
4. 运行 `python scripts/validate_note.py <笔记路径>` 校验
5. 校验通过后提交，提交信息写清这篇笔记解决什么问题

## 决策点

- **这批经验只值一段话？** → 不新建笔记，补进已有笔记的对应小节
- **经验主要是代码实现？** → 代码放 `Demos/examples/`，笔记只写"为什么这么做"和"踩了什么坑"
- **已经有笔记覆盖了这个主题？** → 改已有笔记，不新建重复文件
- **一件事需要多篇才能讲清？** → 拆成索引页 + 多篇子笔记，索引页只放导航
- **分类目录拿不准？** → 看同主题的现有笔记放在哪，不要自己新建分类

## 边界与失败处理

- 涉及密钥、内网地址、客户数据的内容**不写进笔记**，只写"该配置项叫什么、放在哪"
- 校验脚本报错时先修再提交，不要绕过校验
- 一篇笔记只服务一个主题；发现自己在写"以及""顺便"就拆开
- 引用外部资料时给出来源链接，不要只写结论

## 产出格式

- 标题用中文，说清主题而不是抽象名词
- 开头一段说清"这篇解决什么问题、什么时候该翻它"
- 代码块必须标语言，路径、命令、文件名一律用反引号包起来
- 结尾列"相关笔记"，用相对路径链接到 `../` 下的其它笔记
- 篇幅控制在 300 行以内；超了先问自己是不是该拆成两篇
