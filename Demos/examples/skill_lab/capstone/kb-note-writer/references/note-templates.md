# 笔记模板

> 三种形态各一套。先判断形态，再选模板。

## 形态判断

| 形态 | 什么时候用 | 特征 |
| --- | --- | --- |
| **单篇笔记** | 一个主题能在一篇里讲清 | 有自己的 H1，路径形如 `AI/RAG/分块策略.md` |
| **索引页** | 一个主题需要多篇才讲得清 | 只列导航和一句话摘要，没有大段正文 |
| **补充已有笔记** | 经验只值一段话 | 不新建文件，在已有笔记里加小节 |

---

## 模板一：单篇笔记

````markdown
# <主题中文名>

<一段话说清：这篇解决什么问题、什么时候该翻它。不超过 3 句。>

## 背景 / 问题

<为什么需要这个东西。没有背景就不要写这一节。>

## 做法

<核心内容。给出判断依据，不要只给命令。>

```python
# 关键代码，带注释说明"为什么这么写"
```

## 取舍

<为什么选这个方案，放弃了什么。>

## 坑

<踩过的具体坑，一行一条。>

## 相关笔记

- [相关主题](../分类/其它笔记.md)
````

---

## 模板二：索引页

````markdown
# <主题中文名>

<一段话说清这个主题覆盖什么。>

## 子笔记

| 笔记 | 解决什么 |
| --- | --- |
| [子笔记 A](子笔记A.md) | ... |
| [子笔记 B](子笔记B.md) | ... |

## 阅读顺序

<从哪篇开始读、为什么。>
````

---

## 模板三：补充已有笔记

在已有笔记里加小节，标题级别跟着上文走：

````markdown
## <新增小节>

<内容。补充已有笔记时不要重复上文已经说过的背景。>
````

---

## 通用要求

1. **标题用中文**，说清主题而不是抽象名词（`检索分块策略` 好过 `分块`）
2. **开头第一段**说清"解决什么问题、什么时候翻它"——这是别人唯一会读的部分
3. **代码块标语言**；路径、命令、文件名用反引号
4. **写判断依据，不写操作复读**：解释"为什么选它"，而不是把文档抄一遍
5. **"坑"是最值钱的部分**，别省
6. **相关笔记**用相对路径链接，连不上就是错的
7. 篇幅 **300 行以内**；超了先考虑拆成两篇
