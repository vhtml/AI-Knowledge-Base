# 指标字典与指标树 · 工单自动归档助手

三层结构：**北极星**（我们要提升什么）→ **护栏**（提升它不能牺牲什么）→ **诊断**（它为什么涨/跌）。

---

## 北极星指标

| 项 | 内容 |
| --- | --- |
| 名称 | 周成功自动归档工单数 |
| 定义 | 统计周期内被系统自动归档、且 24 小时内未被人工改判的工单数量 |
| 计算口径 | 归档日志 ∩ 未改判日志，按自然周聚合，去重工单 ID |
| 目标 | 上线第 8 周达到 600 单/周 |
| 数据源 | 工单系统归档日志 + 改判日志 |
| 负责人 | 产品负责人 |
| 可判定性 | 是。判定规则写死在埋点里，两张表可离线核对，不依赖人工解释 |

选它的理由：它同时包含"系统做了多少"和"做对了多少"——
只用"自动归档工单数"会在准确率下滑时看起来更好看，那是反向激励。

---

## 护栏指标

护栏是"北极星再好也不能违反"的底线。任何一条护栏破线，暂停放量。

| 名称 | 定义 | 阈值 | 负责人 |
| --- | --- | --- | --- |
| 自动归档准确率 | 自动归档工单中未被改判的比例 | ≥ 95% | 算法负责人 |
| 人工改判率 | 自动归档工单在 24 小时内被人工改判的比例 | ≤ 5% | 客服运营 |
| 单工单模型成本 | 每处理一单工单产生的模型与检索成本 | ≤ 0.08 元 | 工程负责人 |
| 高危误操作次数 | 退款、改派、改标签等不可逆动作的错误执行次数 | 0 次 | 风控 |
| P95 分类延迟 | 工单创建到分类结果返回的耗时的 95 分位 | ≤ 3 秒 | 工程负责人 |

护栏缺失是这套体系最常见的失败方式：只有北极星时，
"把准确率降到 80% 换吞吐"永远是一个看起来很划算的提议。

---

## 诊断指标

诊断指标回答"北极星为什么是这个数"，不承担考核。

| 名称 | 回答什么问题 | 看的方式 |
| --- | --- | --- |
| 分类置信度分布 | 低置信样本占比多少，是否集中在某类工单 | 按标签分组的置信度直方图 |
| 改判 Top 原因 | 人工改判最常见的原因是标签定义、检索缺失还是模型能力 | 改判原因标签计数 |
| 分标签检索命中率 | 哪些标签经常检索不到对应语料 | 每个标签的命中率与召回条数 |
| 渠道结构占比 | 工单来源结构变化是否让场景分布偏移 | 各渠道工单占比周环比 |
| 标签口径变更记录 | 最近一次口径变更是什么时候，改了什么 | 变更登记表 |

## 漏斗

| 环节 | 人数（试点期样本） | 较上一环节 | 全链路占比 |
| --- | --- | --- | --- |
| 进入工单系统 | 10000 | — | 100% |
| 开启自动归档 | 4200 | 42.0% | 42.0% |
| 首次自动归档 | 3100 | 73.8% | 31.0% |
| 首次归档正确 | 2700 | 87.1% | 27.0% |
| 第二周仍在使用 | 1600 | 59.3% | 16.0% |
| 第四周仍在使用 | 1150 | 71.9% | 11.5% |

全链路转化 11.5%。最该盯的不是总量，而是「首次归档正确 → 第二周仍在使用」这一环：
掉了 41%，说明用户被正确分类过一次之后依然不回来——问题在体验或信任，不在模型准度。
