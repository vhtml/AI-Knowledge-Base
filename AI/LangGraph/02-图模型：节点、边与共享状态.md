# 02 · 图模型：节点、边与共享状态

> **这篇要回答**：LangGraph 到底把 Agent 表达成了什么？节点、边、状态三者怎么配合？一次 `invoke` 内部到底发生了什么？

---

## 1. 核心比喻：状态机，不是流程图

大多数人第一次接触 LangGraph 会把它当成"流程图工具"。**这个理解会让你写出跑得通但不敢上生产的代码。**

更准确的说法是：**LangGraph 是一台状态机**。

```
       读状态            写状态（部分更新）
   ┌──────────┐   ┌──────────────────┐
   │  节点     │──►│  归约器：怎么合并  │
   │  Node     │   │  Reducer         │
   └──────────┘   └──────────────────┘
        ▲
        │ 边决定"下一步是谁"
   ┌────┴─────┐
   │  Edge    │
   │  静态/条件 │
   └──────────┘
```

流程图关心的是"事情按什么顺序做"，状态机关心的是**"当前处于什么状态、下一步允许去哪"**。
这个差别在生产上的代价很直接：流程图画错了，重跑一遍就好；状态机设计错了，
用户会拿到一个半成品状态，而那个状态可能已经被写进数据库了。

---

## 2. 四个基本概念

| 概念 | 是什么 | 代码里的样子 |
| --- | --- | --- |
| **State** | 节点之间共享的数据结构，图的"内存" | `class State(TypedDict)` |
| **Node** | 一个普通函数：读状态 → 返回**部分更新** | `def my_node(state) -> dict` |
| **Edge** | 决定下一个执行哪个节点 | `add_edge` / `add_conditional_edges` |
| **Compiled graph** | 装好节点和边之后 `compile()` 出来的可执行对象 | `graph = builder.compile()` |

三个最容易踩的点：

1. **节点返回的是"更新"，不是"新状态"。**
   节点只写它想改的键，其余键保持不变。直接 `state["x"] = 1` 修改入参**不会**生效。
2. **节点签名第一个参数永远是 state**，可以再加 `config` 之类的可注入参数。
3. **`compile()` 之前的东西不执行**。构建图和运行图是两件事，别把 `builder.add_node` 当成"跑了一下"。

## 3. 一次 invoke 内部发生了什么

LangGraph 底层的执行引擎叫 **Pregel**（图计算里 BSP 模型的那套）。一次运行被切成若干个 **super-step**：

```
super-step 0:  START ──► node_a ──► node_b        ← 这一步里 a、b 可以并行
super-step 1:  node_b ──► node_c                    ← 有边连着的，顺序执行
super-step 2:  node_c ──► END
```

三条关键推论：

- **同一个 super-step 里的节点彼此看不到对方的更新**，只看到上一个 super-step 结束时的状态快照。
  这就是为什么并行分支需要**归约器**来合并结果（第 3 章）。
- 每个 super-step 结束都可以落一个**检查点**（第 7 章），这是持久化的最小粒度。
- 循环不是特殊机制，就是"边指回了前面的节点"。要防止死循环，靠 `recursion_limit`。

```python
graph.invoke(input, config={"recursion_limit": 10})
```

## 4. 边有两种

```python
# 静态边：固定下一步
builder.add_edge("node_a", "node_b")

# 条件边：根据状态选下一步
builder.add_conditional_edges(
    "router",
    lambda state: "yes_node" if state["ok"] else "no_node",
)
```

还有第三种：`add_sequence(["a", "b", "c"])`，等价于连一串静态边。

条件边里的函数**只负责选路，不负责改状态**。
如果既要改状态又要选路，用 `Command`（第 4 章）。

> **一个高频坑**：条件边的**路由函数**和**节点函数**是两回事。
> 节点函数返回 `dict`（状态更新），路由函数返回**字符串**（下一个节点名）。
> 把两者写成一个函数，编译期不报错，运行期直接抛
> `InvalidUpdateError: Expected dict, got long`。

## 6. 两种运行方式

| 方式 | 返回 | 什么时候用 |
| --- | --- | --- |
| `invoke(input)` | 最终状态 | 单次跑完拿结果 |
| `stream(input, stream_mode=...)` | 增量事件流 | 要做实时输出、要显示进度 |

流式有 5 种模式（`values` / `updates` / `messages` / `custom` / `debug`），
第 9 章逐个拆。

## 7. 最小完整例子

```python
from typing_extensions import TypedDict
from langgraph.graph import START, StateGraph

class State(TypedDict):
    text: str

def shout(state: State) -> dict:
    return {"text": state["text"].upper()}

builder = StateGraph(State)
builder.add_node("shout", shout)
builder.add_edge(START, "shout")
graph = builder.compile()

graph.invoke({"text": "hello"})
# {'text': 'HELLO'}
```

配套实验：`Demos/examples/langgraph_lab/lessons/ch02_graph_basics.py`

---

## 一句话结论

> **LangGraph 画的不是流程，是状态与状态之间的转移契约。**
> 节点只写它改的键，边只决定下一步去哪，而 `compile()` 之后的那台 Pregel 引擎
> 才是真正在跑的东西——一次运行 = 若干 super-step，每步结束都可能落一个检查点。
