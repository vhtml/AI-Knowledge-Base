# Skill 制作 · 七天系统教程

这个目录回答一个问题：**怎么把一段"人肉经验"封装成一个 Agent 能自动加载、自动执行、可分发复用的技能包。**

配套实验在 [`Demos/examples/skill_lab/`](../../Demos/examples/skill_lab/)，每天一个主题、一篇笔记、一个能跑的练习，
最后产出一个**通过官方校验、可打包成 `.skill` 的发布级技能**。

---

## 这套教程的前提假设

- 目标读者：会写 Python 和 Markdown，但没系统做过 skill 的人
- 目标产物：**发布级技能**——有精确的触发设计、可复用资源、可运行的脚本、能打包分发
- 时间投入：每天 1–2 小时，一周走完；也可当长期手册按需查阅

## 怎么跑实验

所有实验都在 `Demos/` 这层 Python 工程里，依赖用 `uv` 管理：

```bash
cd Demos/examples

# 跑某一天的实验
uv run --project .. python -m skill_lab day3

# 跑全部七天
uv run --project .. python -m skill_lab all

# 自检（不依赖 pytest，验证实验骨架本身没坏）
uv run --project .. python -m skill_lab.selftest
```

实验全部**离线运行**：不联网、不消耗 token、不调用模型。
所有断言写在实验代码里，跑挂了就是没学会。

## 毕业标准

走完七天，你手上应该有一个真实的技能包，满足全部条件：

- [ ] `description` 能准确触发，也能在该不触发时保持沉默
- [ ] 正文在 500 行以内，细节分流到 `references/`
- [ ] 有至少一个**被真正执行过**的脚本，退出码和报错信息可用
- [ ] 通过 `quick_validate.py` 校验
- [ ] 能打包成 `.skill`，并安装到本机后被正确识别

第七天实验的输出就是这份毕业作品：`Demos/examples/skill_lab/capstone/`。

## 一句话结论

> Skill 的本质不是"给模型塞更多提示词"，而是**用最少的常驻成本，换取一个在正确的时刻自动展开的完整工作手册**。
> 做得好的 skill，正文可能很长，但常驻在上下文里的永远只有几十个 token 的 description。
