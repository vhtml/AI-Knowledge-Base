# 07 · 打包分发与生态

> **这篇要回答**：怎么把一个技能目录变成可分发的 `.skill` 包？怎么装到机器上？它和 Plugin、MCP 怎么分工？

---

## 1. 发布的三道关

```
① 结构关   有没有 SKILL.md？frontmatter 合法吗？目录干净吗？
② 质量关   触发准不准？脚本跑不跑得通？正文会不会超预算？
③ 分发关   打包成 .skill → 装到目标机器 → 验证被识别
```

第 ① 道有官方脚本，第 ③ 道也有。第 ② 道是第 6 天讲的自建评测。

---

## 2. 校验：`quick_validate.py`

官方脚手架自带校验器：

```bash
python ~/.claude/skills/skill-creator/scripts/quick_validate.py <技能目录>
```

### 它到底检查什么

从源码里读出的完整规则（`quick_validate.py`）：

| 检查项 | 规则 | 失败信息 |
| --- | --- | --- |
| SKILL.md 存在 | 必须 | `SKILL.md not found` |
| frontmatter 起始 | 必须以 `---` 开头 | `No YAML frontmatter found` |
| frontmatter 格式 | `^---\n(.*?)\n---` 正则 | `Invalid frontmatter format` |
| YAML 可解析 | 必须是字典 | `Invalid YAML in frontmatter: ...` |
| 键白名单 | 只允许 `name` `description` `license` `allowed-tools` `metadata` | `Unexpected key(s) in SKILL.md frontmatter: ...` |
| `name` 存在 | 必填 | `Missing 'name' in frontmatter` |
| `name` 类型 | 字符串 | `Name must be a string, got ...` |
| `name` 命名 | `^[a-z0-9-]+$` | `Name '...' should be hyphen-case ...` |
| `name` 边界 | 不能 `-` 开头/结尾，不能 `--` | `Name '...' cannot start/end with hyphen ...` |
| `name` 长度 | ≤ 64 字符 | `Name is too long (...)` |
| `description` 存在 | 必填 | `Missing 'description' in frontmatter` |
| `description` 类型 | 字符串 | `Description must be a string, got ...` |
| `description` 尖括号 | 不能含 `<` `>` | `Description cannot contain angle brackets` |
| `description` 长度 | ≤ 1024 字符 | `Description is too long (...)` |

**注意它不检查什么**：正文行数、references 深度、有没有多余的 README、脚本能不能跑。
这些要靠你自己（第 4、5 天）和 `skill-refiner` 那类工具补。

## 3. 打包：`package_skill.py`

```bash
python ~/.claude/skills/skill-creator/scripts/package_skill.py <技能目录> [输出目录]
```

行为：

1. **先校验**——校验不过直接退出，不产出包
2. 校验通过 → 用 zip 打包成 `<技能名>.skill`
3. 包内路径**包含技能目录名作为根**（`arcname = file_path.relative_to(skill_path.parent)`）

```
my-skill.skill
└── my-skill/
    ├── SKILL.md
    ├── references/
    └── scripts/
```

第 3 点很重要：**解压后自带目录名**，不会污染目标目录。

### `.skill` 就是个 zip

```bash
unzip -l my-skill.skill
```

不需要专用工具，任何 zip 工具都能处理。这也是它比 Plugin 更轻的原因。

## 4. 安装：三种位置

MiniMax Code（MCode）没有 skill CLI，靠文件位置 + 原生 `skill` 工具：

| 类型 | 路径 | 可见范围 |
| --- | --- | --- |
| 内置 | `~/.minimax/.builtin-skills/<name>/SKILL.md` | 所有 agent，**受保护** |
| 用户级 | `~/.minimax/skills/<name>/SKILL.md` | 所有 agent |
| agent 私有 | `~/.minimax/agents/<agent>/skills/<name>/SKILL.md` | 仅该 agent |

### 从 Git 装

```bash
git clone <git-url> ~/.minimax/skills/<name>
```

要求：**仓库根目录就有 `SKILL.md`**。

### 生效时机

> **技能在下个会话生效**，不需要重启运行时。

装完改完，下一个会话用 `skill({ name: "<name>" })` 验证。

### 第三方技能包与版本锁定

本仓库通过 `skills-lock.json` 锁定了 **22 个 LangChain 官方技能**。锁文件结构：

```json
{
  "version": 1,
  "skills": {
    "deep-agents-core": {
      "source": "langchain-ai/langchain-skills",
      "sourceType": "github",
      "skillPath": "config/skills/deep-agents-core/SKILL.md",
      "computedHash": "78899a82..."
    }
  }
}
```

| 字段 | 含义 |
| --- | --- |
| `source` | 来源（GitHub 仓库 `owner/repo`，或本地路径） |
| `sourceType` | `github` / `local` |
| `skillPath` | 该技能在来源仓库中的位置 |
| `computedHash` | 内容哈希，用于检测上游变更 |

配套的 `.gitignore` 规则（把 vendor 下来的技能目录排除出版本库）：

```gitignore
# agent skills (vendored from npx skills; version pinned in skills-lock.json)
.minimax/skills/
```

**要点：锁文件进版本库，vendor 目录不进。**
这样同事拉代码时拿到的是"同样的技能、同样的版本"，而不是各自装的最新版。

> 本仓库这条链路由 `chore/langchain-skills` 分支引入，不在 `main` 上。

## 5. 生态位：Skill / Plugin / MCP 怎么分工

| | 是什么 | 装在哪 | 适合 |
| --- | --- | --- | --- |
| **Skill** | 一个知识/流程包 | `skills/<name>/` | 教模型"怎么做某类事" |
| **Plugin** | 一组 App + MCP + Skill + Hook 的打包 | `~/.minimax/plugins/<name>/` | 分发一整套能力 |
| **MCP Server** | 运行时工具服务 | MCP 配置里 | 让模型能读写外部系统 |

**一个 Plugin 可以打包多个 Skill**，所以：

- 只发布知识/流程 → **Skill** 就够
- 要连带发布工具、鉴权、命令钩子 → 上 **Plugin**
- 要让模型访问外部数据源 → 上 **MCP**

本机的 `plugin-creator` 技能负责 Plugin 的搭建与校验，路径是 `~/.minimax/plugins/`。

## 6. 发布前检查清单

```
□ quick_validate.py 通过
□ description 触发评测达标（该触发触发、不该触发闭嘴）
□ 所有脚本都实跑过，退出码正确
□ 正文 ≤ 500 行
□ references 只一层深，>100 行有目录
□ 没有 README / CHANGELOG / 安装指南
□ 用不上的脚手架示例文件已删除
□ 打包后能在干净环境解压、安装、被识别
```

## 7. 本章练习

```bash
cd Demos/examples && uv run --project .. python -m skill_lab day7
```

练习做三件事：

1. **校验**：用 `quick_validate.py` 检查自己写的技能，看错误信息怎么引导你修
2. **打包**：用 `package_skill.py` 产出 `.skill`，`unzip -l` 看包内结构
3. **安装验证**：装到临时目录 → 模拟"下一个会话" → 确认能被识别

最后完成**毕业作品**：`Demos/examples/skill_lab/capstone/` 下的 `kb-note-writer`。

---

## 8. 本章要点

- 三道关：**结构**（官方校验器）、**质量**（自建评测）、**分发**（打包安装）
- `quick_validate.py` 只管 frontmatter，正文质量要自己把关
- `.skill` 就是 zip，解压自带技能目录名
- MCode 三个安装位置 + **下个会话生效**
- 第三方技能用 **lock 文件锁版本**，vendor 目录不进版本库
- Skill 管知识、Plugin 管整包能力、MCP 管外部访问
