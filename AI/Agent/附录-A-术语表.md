# 附录 A · 术语表

按主题分组，每条给出**一句话定义 + 一个判别问题**。
判别问题是关键：能回答"这个东西是它吗"，比能背下定义有用得多。

---

## 一、模型与协议

| 术语 | 定义 | 判别问题 |
| --- | --- | --- |
| **Token** | 模型处理文本的最小单位，英文约 4 字符 1 个，中文约 1 字 1 个 | 我说的"1000 字"在账单上是 1000 token 吗？ |
| **上下文窗口** | 一次请求能携带的最大 token 数（输入 + 输出） | 我的历史 + 输出预留加起来超了吗？ |
| **Prompt / 提示词** | 发给模型的全部文本，包括系统提示、历史、检索内容 | 哪些字是"指令"，哪些是"数据"？ |
| **System Prompt** | 设定模型行为边界的最高优先级指令 | 它该在消息数组的哪个位置？ |
| **Temperature** | 采样随机性，0 最确定 | 我的任务需要复现吗？需要就设 0 |
| **Max Tokens** | 输出上限 | 被截断时 `finish_reason` 是什么？ |
| **Top-p** | 核采样，只在累积概率前 p 的候选里采样 | 和 temperature 一起调过吗？通常只需调一个 |
| **Finish Reason** | 模型停止的原因：`stop` / `length` / `tool_calls` / `content_filter` | 这个响应能直接用吗？ |
| **Usage** | 本次调用的 token 统计 | 输入和输出差了多少倍？ |
| **System Prompt 与上下文预算** | 系统提示每轮重发 | 乘以轮次是多少钱？ |
| **Structured Output（结构化输出）** | 让模型按 JSON Schema 输出 | 输出过校验吗？ |
| **Reasoning Model（推理模型）** | 先产出思考过程再回答的模型 | 这个任务真的需要推理吗？ |
| **Thinking Budget（思考预算）** | 允许模型花多少 token 思考 | 简单任务也要开满预算吗？ |
| **Prompt Cache（提示缓存）** | 复用相同前缀的缓存，降低输入单价 | 你的提示前缀稳定吗？ |

## 二、Agent 结构

| 术语 | 定义 | 判别问题 |
| --- | --- | --- |
| **Agent** | 自主决定下一步做什么的循环 | 下一步是模型选的还是人写死的？ |
| **ReAct** | Reason + Act 交替：想一步、做一步、看结果、再想 | 模型和工具之间是否有反馈回路？ |
| **Agent Loop（循环）** | 模型 → 工具 → 回填 → 模型 的重复结构 | 它靠什么终止？ |
| **Tool Call（工具调用）** | 模型提出的调用意图 | 是意图还是已经执行完的结果？ |
| **Tool Message** | 工具执行结果回填给模型的消息 | 带 `tool_call_id` 了吗？ |
| **Trajectory（轨迹）** | 一次运行的完整步骤序列 | 我能回放它吗？ |
| **Workflow（工作流）** | 步骤由人写死的编排 | 路由规则是谁定的？ |
| **Harness（脚手架）** | 预置规划、文件管理、子智能体等能力的运行时 | 它替我省掉了哪些工作？ |
| **Sub-agent（子智能体）** | 被主 Agent 委派执行子任务的 Agent | 它有独立的上下文吗？ |
| **Plan（计划）** | 对任务步骤的预先分解 | 计划是写死一次还是能重规划？ |
| **Reflection（反思）** | 生成 → 批评 → 修订 的自纠错流程 | 这里有外部验证吗？ |
| **Orchestration（编排）** | 多个 Agent 或多个步骤的协作方式 | 拓扑是哪一种？ |

## 三、上下文与记忆

| 术语 | 定义 | 判别问题 |
| --- | --- | --- |
| **Context（上下文）** | 本轮喂给模型的全部信息 | 每一部分分了多少预算？ |
| **Context Window Budget（上下文预算）** | 上下文窗口在系统提示、历史、工具结果、输出预留之间的分配 | 各部分配额之和等于总窗口吗？ |
| **Context Rot（上下文腐化）** | 长对话中段信息权重下降的现象 | 关键信息被埋在中间了吗？ |
| **Compaction（压缩）** | 把旧消息压成摘要以节省预算 | 压掉的是不是关键约束？ |
| **Short-term Memory（短期记忆）** | 会话内的工作记忆 | 换会话还在吗？ |
| **Long-term Memory（长期记忆）** | 跨会话持久化的信息 | 用户能改吗？能删吗？ |
| **Memory Retrieval（记忆检索）** | 从长期记忆里召回相关条目 | 未召回的记忆会进上下文吗？ |
| **Memory Poisoning（记忆污染）** | 错误信息被写入记忆后持续影响后续会话 | 用户能纠正它吗？ |
| **RAG（检索增强生成）** | 检索外部知识片段注入上下文 | 检索的是"外部知识"还是"关于用户的事实"？ |
| **Progressive Disclosure（渐进式披露）** | 资源按需加载而非一次性全塞 | 什么时候加载下一层？ |
| **Summarization（摘要）** | 用压缩文本替代原文 | 有损的部分能接受吗？ |

## 四、工具与能力

| 术语 | 定义 | 判别问题 |
| --- | --- | --- |
| **Tool Schema** | 模型的工具说明书（name/description/parameters） | 模型只能看到 schema，看不到我的实现 |
| **Field Description** | 参数级说明 | 它落到字段级了吗？还是只写了函数级？ |
| **Granularity（粒度）** | 一个工具覆盖多宽的任务范围 | 一个工具 = 一个用户意图吗？ |
| **Error Surface（错误面）** | 工具失败时把什么信息回给模型 | 模型看得懂这个错误吗？能自我纠正吗？ |
| **Idempotency（幂等性）** | 重复执行不产生额外副作用 | 重试会重复扣款吗？ |
| **MCP（模型上下文协议）** | 让工具以标准协议暴露给模型的规范 | 工具接入走的是这个标准吗？ |
| **MCP Client / Server** | 协议两端：客户端消费工具，服务端提供工具 | 谁在宿主进程里？ |
| **Tool Choice** | 强制模型是否调用工具、调用哪个 | 需要强制时用了哪个模式？ |
| **Parallel Tool Calls** | 一轮里模型请求多个工具 | 部分失败时怎么处理？ |
| **Function Calling** | 工具调用的通用叫法 | 和 Tool Calling 是同一个东西 |

## 五、生产工程

| 术语 | 定义 | 判别问题 |
| --- | --- | --- |
| **HITL（人在环路）** | 人参与 Agent 决策或审批的机制 | 哪些动作必须人点头？ |
| **Approval Gate（审批关卡）** | 高危操作执行前的强制确认 | 按风险分级还是按工具分级？ |
| **Trace（追踪）** | 一次运行的完整事件记录 | 我能定位到具体哪一步吗？ |
| **Span（跨度）** | 追踪里的一个操作单元 | 父子关系对吗？ |
| **Replay（回放）** | 用记录的事件重现一次运行 | 重放能复现同样结果吗？ |
| **Golden Set（黄金集）** | 固定的评测样本集 | 改动前后能跑出可比对的分数吗？ |
| **Trajectory Eval（轨迹评测）** | 不只看结果，还看执行路径 | 该不该调的工具调了吗？ |
| **LLM-as-judge** | 用模型给模型输出打分 | 评委和被评是不是同一个模型？ |
| **Regression Gate（回归门禁）** | 分数低于阈值就阻断合并 | 这个门禁在 CI 里吗？ |
| **Circuit Breaker（熔断）** | 连续失败后停止打后端 | 熔断后走什么路？ |
| **Fallback（降级）** | 主路径失败时的备用路径 | 降级后用户看到什么？ |
| **Backoff（退避）** | 重试时逐步拉长等待时间 | 有加抖动吗？ |
| **Prompt Injection（提示注入）** | 外部内容里藏指令骗模型执行 | 工具结果被当指令了吗？ |
| **Least Privilege（最小权限）** | 只给 Agent 完成任务的最低权限 | 这个工具能删数据吗？ |
| **Sandbox（沙箱）** | 隔离的执行环境 | 能访问哪些目录和网络？ |
| **TTL（存活时间）** | 数据过期时间 | 过期后是删还是归档？ |
| **Unit Economics（单位经济）** | 单次任务的成本与收益 | 单次任务毛利是正的吗？ |

## 六、评测与观测

| 术语 | 定义 | 判别问题 |
| --- | --- | --- |
| **Task Success Rate** | 任务成功率 | 分母是什么？ |
| **Step Efficiency** | 达成结果所走的步数 | 理想步数是多少？ |
| **Tool Call Distribution** | 工具调用频次分布 | 有没有工具从没被调用过（= 描述写坏了）？ |
| **Failure Rate** | 失败占比 | 按工具分还是按错误类型分？ |
| **TTFT** | 首 token 延迟 | 用户等多久看到第一个字？ |
| **Throughput** | 单位时间处理的 token 数 | 吞吐和延迟是一回事吗？ |
| **Eval Set Overfitting** | 评测集被"考熟"了 | 样本是不是都来自同一类场景？ |
| **Deterministic Path** | 用脚本化模型跑，断言严格可复现 | 回归测试靠的是它吗？ |

## 七、最容易混淆的三组

**1. Workflow vs Agent**
- Workflow：路由由人写死；Agent：路由由模型选。
- 判别：把模型换成规则，结果会变吗？会变 → Agent。

**2. 上下文 vs 记忆**
- 上下文：这一轮发给模型的全部信息。
- 记忆：跨轮次持久化、需要检索才能进上下文的信息。
- 判别：换会话后它还在吗？在 → 记忆。

**3. 反思 vs 重试**
- 反思：带着批评意见改一版。
- 重试：同一输入再试一次。
- 判别：第二次尝试的信息里有没有"批评意见"？

## 八、这份教程的三个术语约定

- **"手写运行时"**：指不依赖任何 Agent 框架、用标准库实现的 Agent 循环（第 1–16 章）。
- **"框架"**：指 LangChain / LangGraph / Deep Agents 这类提供现成抽象的库（第 17 章才引入）。
- **"真实路径"**：指接 `Demos/.env` 里配置的真实模型端点；**"确定性路径"**指脚本化假模型。
  两者在本教程里是严格区分的——默认走确定性路径。
