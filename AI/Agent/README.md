# Agent 开发 · 十七章系统教程

这个目录回答一个问题：**Agent 到底是怎么工作的、每一环在生产里会怎么崩、以及你要怎么亲手把它造出来。**

配套实验在 [`Demos/examples/agent_lab/`](../../Demos/examples/agent_lab/)，一章一篇笔记、一个能跑的实验，
最后产出一个**带上下文预算、带记忆、带审批、带评测**的完整 Agent。

> **这套教程刻意不使用任何 Agent 框架。**
> 全部实验只用标准库加 `openai` SDK，从零手写运行时。
> 原因很简单：框架替你写了循环，你就永远看不清"框架到底替我做了什么"。
> 第 17 章才把每一环映射回 LangGraph / LangChain / Deep Agents——那时候你已经知道该找什么了。

## 这套教程的前提假设

- 目标读者：会写 Python，知道"大模型能调用函数"，但没系统做过 Agent 的人
- 目标产物：**一个能上生产的 Agent 运行时**——不是 demo，是有预算、有护栏、有评测的那种
- 时间投入：每章 1–2 小时；也可以当长期手册按需查阅
- 语言基线：Python 3.13，只用标准库 + `openai` SDK，不引入 Agent 框架

## 怎么跑实验

所有实验都在 `Demos/` 这层 Python 工程里，依赖用 `uv` 管理：

```bash
cd Demos/examples

# 跑某一章
uv run --project .. python -m agent_lab ch07

# 跑全部十七章
uv run --project .. python -m agent_lab all

# 自检（验证笔记与实验一一对应，且断言都还成立）
uv run --project .. python -m agent_lab selftest

# 列出所有章节
uv run --project .. python -m agent_lab list
```

### 两条运行路径

| 路径 | 触发方式 | 模型来源 | 用途 |
| --- | --- | --- | --- |
| 确定性路径 | 默认 | 脚本化假模型 | 学习与回归，断言严格、结果可复现 |
| 真实路径 | `--live` | `Demos/.env` 里的 OpenAI 兼容端点 | 看真模型怎么跑，断言只校验形状 |

```bash
# 第 7 章用真实模型再跑一遍
uv run --project .. python -m agent_lab ch07 --live

# 全部章节走真实路径
uv run --project .. python -m agent_lab live
```

真实路径读 `Demos/.env` 的 `LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL`（仓库既有约定）。
没配也不要紧——会明确告诉你要补哪个变量，而不是在 HTTP 层报 401。

> **为什么默认走确定性路径**：真实模型的输出不确定，断言写不死，
> 实验就退化成"看一眼觉得差不多"。确定性路径能把每条结论钉成可复现的断言，
> 真模型路径用来确认"脚本里的形状和真模型对得上"。

## 毕业标准

走完十七章，你手上应该有一个真实的 Agent 运行时，满足全部条件：

- [ ] 能说清一个 Agent 的四个必要条件，并解释为什么缺一个就不再是 Agent
- [ ] 有手写的 ReAct 循环，工具错误会**回填给模型**而不是直接崩掉
- [ ] 工具的参数说明落在**字段级**，模型的参数错误能被它自己纠正
- [ ] 有一张上下文预算表，知道每一部分分多少、什么绝对不能压
- [ ] 记忆有写入、检索、遗忘三条完整路径，且支持用户更正
- [ ] 重试策略**按失败类型选**，不是一把梭
- [ ] 有 trace，Agent 出问题能回放到具体哪一步
- [ ] 有一份黄金集，改动前后能跑出可比对的分数
- [ ] 工具按风险分级，高危操作走人工审批
- [ ] 能算清单次任务的成本，并说出钱烧在哪
- [ ] 知道自己踩了哪些坑，以及框架能替你省掉哪一部分

第 17 章的实验输出就是这份毕业作品的自检清单。

## 一句话结论

> **Agent 的结构只有 12 行，生产的难度全在这 12 行的每一环会怎么崩。**
> 这套教程不教你怎么调框架，它教你**每一环该配什么护栏**——
> 手写一遍之后，你用任何框架都知道该往哪里塞自己的设计。
