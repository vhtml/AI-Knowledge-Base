# 06 · 定位、价值主张与商业模式

> **这篇要回答**：你的产品到底替谁省了什么、凭什么别人付钱、该按什么方式收钱，又有哪些商业风险会先于技术风险出现？

---

## 1. 定位三问：为谁、替代什么、凭什么是你

定位不是一句 slogan，是三个能被证伪的判断。每个判断都要配**判据**和**反例**。

| 问题 | 一句话判据 | 反例（这不算回答） |
| --- | --- | --- |
| **为谁** | 说得清一个**具体角色 + 一个高频场景**，且这个角色现在就有这个痛 | "面向所有人""面向企业用户" |
| **替代什么** | 说得出它今天被什么替代了：某个工具、某个人、还是"忍着不做" | "替代现有方案" |
| **凭什么是你** | 至少有一项是别人短期复制不了的：数据、位置、分发、资质 | "我们模型更强""我们团队更有经验" |

**"为谁"要写角色，不是写市场。**"给法务"是角色，"给中大型企业的法务"是市场，"给中大型企业总部的合同风险审核岗"才是能指导设计的定位。

**"替代什么"是定位里最锋利的一问。**
替代对象分三种，对应三种完全不同的打法：

| 替代对象 | 打法 | 定价锚点方向 |
| --- | --- | --- |
| 某个现有工具 | 迁移成本、兼容性、导入导出 | 与被替工具的价格对齐或略高（须有增量价值） |
| 某个人（岗位人力） | 说服对方上级：省下的时间值多少 | 与人力成本对齐（见第 6 节） |
| "忍着不做" | 降低启动门槛，先证明有用 | 从零定价，靠低门槛起量 |

**"凭什么是你"直接接第 05 章的差异化四问。**
两个章节的关系：四问给证据，三问给选择。

## 2. 价值主张公式：三个格子 + 一个验证

一句话价值主张不是文案，是一个**结构**（结构示意）。三个格子缺一格都会翻车。

```
┌───────────────┬──────────────────┬──────────────────┐
│ 替谁          │ 在什么情境下       │ 省了什么         │
│ 角色 + 现状    │ 触发点 + 约束     │ 时间/质量/新可能  │
├───────────────┴──────────────────┴──────────────────┤
│ 为什么可信：数据来源 · 流程位置 · 资质 · 可核对证据     │
├───────────────────────────────────────────────────────┤
│ 怎么验证：指标 + 观察方式 + 时限（不是"用户说好用"）    │
└───────────────────────────────────────────────────────┘
```

### 模板：可直接填的句式（示意）

```markdown
为【具体角色】，在【具体情境：什么时候/为什么必须做这件事】下，
把【某项工作】从【原来的做法/耗时/质量基线】变成【新的结果】，
并且比【替代方案】快/准/省在【可指认的环节】。

可信因为：【数据来源】+【流程位置】+【可核对的证据形式】。
验证方式：在【多长时间】内，观察【哪个指标】从【基线】变到【目标】。
```

**三个常见翻车点**：

1. **只讲功能不讲情境**。"能自动生成周报"是功能；"每周五下午不用再花两小时拼周报"才是价值。
2. **可信证据是形容词**。"基于先进的 AI"不是证据；"答案里带原文引用，可点开核对原句"是证据。
3. **验证方式是满意度**。"用户说好用"验证不了价值，只能验证感受；价值要看**行为指标**——用了几次、替代了原来哪一步、有没有减少人工修正。

**产品经理怎么用它**：这句话最终要能拆成落地决策——
"省了什么"决定功能优先级，"为什么可信"决定引用与审计能力要不要投入，"怎么验证"决定第 9 节要埋哪些埋点。

## 3. AI 特有的四类价值来源

不是所有价值都能收钱。四类来源的**付费意愿结构完全不同**。

| 价值类型 | 含义 | 付费意愿来自 | 验证难度 | 适合的收费方式 |
| --- | --- | --- | --- | --- |
| **省时间** | 同样产出，人工投入更少 | 个人（省下的时间）或主管（释放的人力） | 低，用户自己就感知得到 | 席位、订阅、按人力成本锚定 |
| **提质量** | 同样时间，产出更好或更少错 | 组织（返工、错误成本下降） | 高，需要基线和证据 | 分层订阅、按结果或按规模 |
| **开新事** | 原来根本做不了的事 | 愿意为"不可能"付溢价的人 | 中，需要找到真实需求 | 按用量或按项目 |
| **降门槛** | 把专家级能力交给非专家 | 组织（授权与合规） | 高，需要先建立信任 | 席位 + 用量混合 |

### 决策表：你的产品该主打哪一种价值

| 你的处境 | 判断依据 | 该怎么做 | 常见错误 |
| --- | --- | --- | --- |
| 用户已经在做这件事，只是很慢 | 访谈能问出"你上次做它花了多久" | 主打省时间，锚定价=人力成本 | 讲"更智能"，用户只关心省几分钟 |
| 用户做得到但做不好，错误代价高 | 存在返工、投诉、审核环节 | 主打提质量，把证据链做成产品功能 | 只提高流畅度，不给可核对的依据 |
| 用户想做但缺能力/缺数据 | 需求里出现"我们一直想但做不了" | 主打开新事，从低价试水 | 拿新场景当主战场却按老场景定价 |
| 用户是业务人员，能力在专家那里 | 专家时间被占用是主要痛点 | 主打降门槛，卖给组织而非个人 | 卖给个人却用组织级能力定价，采购走不通 |

**一个重要判断**：省时间是**最好卖也最容易被压价**的价值。
因为它天然有一个上限（人力成本），而竞品和客户都会拿这个上限压你。
想避免被压价，通常要往上叠加"提质量"或"开新事"。

## 4. 定价四模型

| 模型 | 怎么收 | 优点 | 缺点 | 适合 |
| --- | --- | --- | --- | --- |
| **席位制** | 按人头/按账号，按月或年 | 收入可预测，采购好走流程 | 与"少数人高频用"的现实不符；重度用户吃光毛利 | 使用者分散且人数稳定 |
| **用量制** | 按 token / 任务数 / API 调用 | 与成本直接对齐 | 用户怕账单失控；与用户获得的价值脱钩 | 用量差异极大、成本随用量线性增长 |
| **结果制** | 按完成的任务、按省下的成本分成 | 与价值最对齐，付费意愿最强 | 计量、归因、验收都难；容易扯皮 | 结果可清晰定义、可验收 |
| **分层制** | 基础 / 专业 / 企业，各层能力与额度不同 | 覆盖不同预算，易于升级销售 | 分层线怎么划是难点；用户会挑层薅 | 绝大多数 B 端产品 |

**AI 特有的一条判断**：纯席位制在 AI 产品里常常失效——AI 工具的使用分布**极度长尾**，少数重度用户贡献大部分用量；
按人头收平价，等于你替重度用户补贴了成本。

**分层怎么划**：优先按**能力档位**分（能不能接自己的数据、能不能调工具、有没有审计），
其次按**用量档位**分。理由是能力分层用户能理解，也容易用"升级"来提客单；
纯用量分层容易被用户认为是"计量不透明"。

## 5. 混合定价与超额计费

实际产品几乎都是混合的。AI 的成本结构使混合成为必需而不是可选（结构示意）。

```
┌──────────────── 基础订阅（覆盖典型用量）────────────────┐
│  含 X 次任务 / Y 个连接 / 基础模型档位                    │
│  超出部分 → 超额计费（按量 / 自动切高档模型 / 需审批）    │
└──────────────────────────────────────────────────────────┘
```

**三种常见混合结构**：

| 结构 | 组成 | 好处 | 风险 |
| --- | --- | --- | --- |
| **基础 + 超额** | 固定订阅覆盖典型用量，超出按量 | 收入可预测 + 不亏本 | 超额费率定高了用户会心疼，定低了被薅 |
| **能力分层 + 模型档位** | 层内包含更强模型与更多上下文，超额自动切档 | 成本随模型档位自然伸缩 | 用户察觉"我的答案变差了"，需要显式告知 |
| **席位 + 用量双轨** | 席位费含基础能力，用量另计 | 适合团队内部分摊 | 采购与财务对账复杂 |

**超额计费必须有的三样东西**：
1. **可预测的预估**：超额前给出"按当前速率本月预计再花 X"的展示
2. **可设上限**：用户能自己设月度封顶，超限后降级而不是继续烧钱
3. **可事后核对**：账单能拆到人、到任务、到模型调用层级

**判断标准**：一个不懂技术的采购看到账单，不应该感到意外。
做不到这一点，再低的报价也会在续约时吵起来。

## 6. 定价锚点：和用户原本要付的人力成本对齐

这是本章最实用的一段。定价锚点不来自竞品价目表，**来自用户今天为这件事付出的真实代价**。

### 计算步骤（示意公式）

```
步骤 1  单用户月节省时间
        = 任务月频次 × (单次原本耗时 − 单次使用后耗时)
步骤 2  单用户月人力成本节省
        = 单用户月节省时间 × 目标用户小时成本
步骤 3  可捕获比例
        = 用户愿意为这份节省支付的金额 ÷ 步骤 2 的结果（需用数据验证，不是行业常数）
步骤 4  定价锚点（上限）= 步骤 2 × 步骤 3
步骤 5  实际定价 = 定价锚点 × 折价系数（由竞争、毛利目标、采购流程共同决定）
```

**步骤 3 是整段里唯一需要你自己验证的数字**。
建议用三个候选值（例如偏低、居中、偏高）做敏感性分析，看收入模型对它的敏感度，
而不是拍一个数写进商业计划。

### 税与毛利的三个提醒

| 提醒 | 含义 | 常见错误 |
| --- | --- | --- |
| **价税分离要写清** | 标价是否含税、税率变化由谁承担 | 含税标价却按不含税算收入 |
| **毛利率要扣变动成本** | 变动成本含模型推理、存储、带宽，不只是模型 API | 只算 API 费用，漏掉存储与向量库 |
| **单位成本会随时间下降** | 模型单价长期下行，同一价格带的产品毛利会改善 | 现在用低价签长约，把未来毛利提前让掉了（单价以 [OpenAI API 定价](https://openai.com/api/pricing/)、[Anthropic 定价](https://www.anthropic.com/pricing) 当日页面为准，核实于 2026-11） |

**一个结构性提醒**：固定席位制 + 成本随用量线性增长，**重度用户会吃光你的毛利**——解法是分层配额、超额计费，或把重度用量单独做成按量包。

**判断锚点是否合理的信号**：
用户听完报价的第一反应是"这个月能省出这么多时间"→ 锚点成立；
第一反应是"市面上更便宜"→ 你在和竞品比价而不是和人力成本比价，锚点没立住。

## 7. 免费策略与成本护栏

免费是分发手段，不是商业模式。**免费用户的边际成本由你承担**，而 AI 的边际成本不是零。

### 三个典型坑

1. **免费用户烧穿成本**：一个不设限的免费层，遇到脚本批量调用就能把当月利润烧光
2. **免费占满好模型**：所有用户共用同一个模型配额，免费用户的排队会拖慢付费用户
3. **免费用户的数据污染付费体验**：免费层的脏数据让检索结果变差，付费用户先受害

### 三种护栏做法

| 做法 | 怎么落地 | 适合 | 代价 |
| --- | --- | --- | --- |
| **降本** | 免费层走小模型、限上下文长度、禁工具调用 | 免费层只是体验入口 | 免费层体验弱，转化率低 |
| **限量** | 每日/月度任务配额，超出排队到下一个周期 | 大多数 B 端 | 用户感知到"用不了"，投诉 |
| **限速排队** | 并发上限 + 每用户速率限制 | API 型产品 | 高峰期体验差，需要排队提示 |

**产品经理怎么用它**：选护栏时先回答"免费层承担的是**分发**任务还是**验证需求**任务"。
若是分发 → 降本 + 限量足够；若是验证需求 → 必须让免费用户能碰到产品的核心价值，否则收集不到有效信号。

**一条硬规则**：免费与付费在**配额、模型档位、数据隔离**上都要分开，
不能让免费用户的行为影响付费用户的延迟与结果质量。

## 8. 单位经济入门

这一节只给关系式和判断口径（示意公式），**完整细算留给本系列第 12 章**（[成本、延迟与单位经济](12-成本、延迟与单位经济.md)）。

```
单客月贡献毛利 = 单客月收入 − 单客月变动成本
毛利率         = 单客月贡献毛利 ÷ 单客月收入
回本周期(月)   = 获客成本(CAC) ÷ 单客月贡献毛利
LTV(粗算)      = 单客月贡献毛利 × 平均留存月数
```

| 指标 | 它回答什么 | 不健康的样子 | 先动哪个杠杆 |
| --- | --- | --- | --- |
| 毛利率 | 一单进来我赚不赚 | 越用越亏 | 降变动成本，或改用超额计费 |
| 回本周期 | 多快回本、现金流压力多大 | 超过一个预算周期 | 缩短销售周期 / 提高首月贡献 |
| LTV/CAC | 增长是否可持续 | 明显小于 1 | 先停下投放，改留存 |
| 留存曲线 | 产品是否真的被需要 | 快速衰减到零 | 回到价值主张与场景选择 |

> 关于 **LTV/CAC 与回本周期的常见经验阈值**（例如 LTV/CAC 达到 3、回本周期控制在一年以内），
> 它只是行业里广泛流传的粗略经验值，**不是任何权威机构发布的结论**，
> 你的业务周期（企业采购、季节性、个人订阅）会显著改变合理区间，请自行校准。

**产品经理怎么用它**：单位经济不是财务同学的表格，是**产品决策的约束条件**。
同一个功能，"免费层开放"和"付费层开放"是两个完全不同的产品决策——
因为它们对贡献毛利的影响方向相反。

## 9. 商业模式风险四类

技术风险会被迭代消化，商业风险不会。

| 风险 | 它怎么发生 | 早期信号 | 早期能做的防御 |
| --- | --- | --- | --- |
| **模型厂商自己下场** | 你的核心价值被上游做成一个默认功能 | 上游发布了与你高度重合的功能页 | 把价值挪到数据与流程位置，不放在模型调用这一层 |
| **API 成本夹住** | 模型单价、上下文长度或调用策略变化，毛利被挤穿 | 变动成本占收入比逐月上升 | 混合定价 + 分层路由（简单任务走小模型） |
| **毛利被大客户谈穿** | 单一客户占比过高，定制化吃掉毛利 | 收入集中 + 定制需求占比高 | 锚定人力成本定价、标准化交付边界 |
| **技术壁垒被复制** | 代码与提示词被模仿，竞品几个月内追平 | 你的功能清单被快速追平 | 把壁垒定义在数据、流程位置与集成深度上 |

**判断风险是否发生在你身上**：把这四类风险各写成一句"如果 X 发生，我会怎样"。
答不出来的那个，就是你的认知盲区——比技术盲区更危险。

**与第 05 章的关系**：风险 1 和风险 4 是差异化四问的反面检查；
风险 2 和风险 3 是第 6、8 节的成本视角。

## 10. 案例拆解：一家客服 AI 创业公司的定价翻车（示意案例）

> 以下为**示意案例**，用于演示"定位—价值—定价—壁垒"的连锁反应，不涉及任何真实公司的内部数据或定价。

| 环节 | 当时的选择 | 后果 |
| --- | --- | --- |
| 定位 | "面向所有客服团队" | 销售只能拼价格 |
| 价值主张 | "自动回复，效率翻倍" | 客户拿它和"多招一个人"比，锚点定低了 |
| 定价 | 按席位低价卖 | 重度客户用量大，毛利被吃穿 |
| 壁垒 | 写成"模型效果好" | 平台方推出同类功能，价格战开打 |

**连锁反应**：定位模糊 → 价值主张没有基线 → 定价锚在竞品而非人力成本 → 毛利被大客户谈穿 → 壁垒站不住。
**如果重来**：先做差异化四问（第 5 节）→ 用定位三问收窄（第 1 节）→ 按定价锚点算价（第 6 节）。

## 11. 常见误区清单

- **定位写成"最智能的 XX"**：没有判据，等于没有定位
- **价值主张只讲功能**：不讲情境和基线，用户无法判断值不值
- **把"可信"写成形容词**：可信要落到可核对的证据形式上
- **定价从竞品价目表倒推**：锚在别人身上，你就是价格接受者
- **用 token 成本当定价**：成本是你的事，价值是客户的事
- **免费换增长但没有护栏**：边际成本由你承担
- **只算收入不算毛利**：用户越多亏得越快的"增长"最危险
- **把模型能力当壁垒**：技术壁垒被复制是时间问题

## 12. 本章练习

**这次练习要用你自己的真实数据。** 示例数据只能验证你算对了，验证不了你的判断——
真数据才会暴露判断里的漏洞。

**输入**：一个真实用户角色 + 他做某件具体任务的当前成本（时间 × 小时成本；成本数字自己核实，不要编市场数据）。

**步骤**：
1. 按第 6 节的五步算定价锚点：单用户月节省时间 → × 小时成本 → 可捕获比例 → 定价区间 → 实际定价；再用目标毛利率倒推出**每用户月成本上限**。
2. 按第 2 节写一句价值主张：三个格子（替谁 / 什么情境 / 省了什么）+ 一句"为什么可信"，再补一条可操作的验证方式。
3. 按第 7 节判断你的免费策略撑不撑得住：免费层承担的是**分发**还是**验证需求**？据此写出成本护栏。
4. 用第 9 节的四类风险各检查一遍，每类写一句"如果 X 发生，我会怎样"。

**产出**：一张定价测算表 + 一句话价值主张 + 一条成本护栏。

**怎么算做对**：
- 定价锚点是从用户省下的钱推出来的，不是从竞品定价抄的；每一步都能追溯到自己的输入假设
- 你能算出"每个用户每月最多能花多少钱"这个上限，并说清它由哪几项决定
- 价值主张里的"怎么验证"是可操作的动作（看哪个指标、从什么基线到什么值、多长时间），不是"大家都会用"

---

## 13. 本章要点

- 定位三问：**为谁（角色 + 场景）/ 替代什么（工具、人、还是忍着不做）/ 凭什么是你**
- 价值主张是结构不是文案：**替谁 + 什么情境 + 省了什么 + 为什么可信 + 怎么验证**
- 四类价值来源付费意愿不同（省时间最好卖但有上限，提质量最难感知但价值不封顶）；定价四模型为席位/用量/结果/分层，纯席位在 AI 产品里常失效
- 混合定价是必需结构：**基础订阅 + 超额**，且必须有预估、上限、事后可核对
- 定价锚点来自**人力成本**，不是竞品价目；可捕获比例要自己验证并做敏感性分析
- 免费层必须有护栏：**降本 / 限量 / 限速**，且免费与付费在配额和模型档位上分开
- 单位经济给关系式，细算留到[第 12 章](12-成本、延迟与单位经济.md)；**贡献毛利和回本周期是产品决策的约束**
- 四类商业风险：**模型厂商下场 / API 成本夹住 / 毛利被谈穿 / 壁垒被复制**

---

## 一句话结论

> **定价的本质是把用户省下的时间换算成他愿意付的钱**：定位说清替谁省，价值主张说清凭什么可信，定价锚点对齐人力成本，单位经济守住毛利——四件事同属一条链。
