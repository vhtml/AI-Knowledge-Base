# 05 · 竞品分析与市场地图

> **这篇要回答**：AI 产品的竞品到底有哪几层？怎么拆才不被功能表骗？自己的差异化到底站不站得住？

---

## 1. 模型层在趋同，差异沉淀在别处

AI 产品最常见的误判是：**把"我们接了更强的模型"当成差异化**。模型能力是入场券，不是护城河。

通用能力的扩散速度很快：同一档模型能力，半年内会被主流厂商普遍覆盖。真正沉下来的差异只有四处：

| 差异来源 | 含义 | 判据（能不能一句话答上来） |
| --- | --- | --- |
| **数据** | 你有、别人拿不到的数据资产 | 列出数据来源清单，其中有独占、独家授权或长期自采的哪一项 |
| **工作流位置** | 你嵌在用户已有的动作链上 | 不用你的产品，用户这一步还能不能做完？不能，就是位置 |
| **分发** | 你触达用户的路径是独占的 | 前三个获客渠道里，有几个不依赖第三方平台 |
| **合规资质** | 某些场景别人进不来 | 牌照、认证、私有化部署、行业准入是否构成硬门槛 |

**产品经理怎么用它**：竞品对比的起点不是"别家有什么功能"，而是"这四类资产，我们分别占了几格"。
四格里占零的，即使功能全对齐，也是脆弱的。

**自检问题**：把两家公司的模型换成同一个，它们的产品还有区别吗？
还有区别 → 差异沉淀在产品层；没区别 → 你只是套壳，模型一升级就会被替代。

> 通用能力与专门能力的分层，可参考 Anthropic 对"工作流 vs Agent"的区分
> （[Building effective agents](https://www.anthropic.com/research/building-effective-agents)，核实于 2026-11）：
> 同样是自动化，不同形态需要的可靠性条件完全不同。

## 2. 竞品四层：你要同时看四个集合（结构示意）

```
                    ┌─────────────────────────────┐
                    │ 上游层：模型 API / Agent 平台 │
                    │  能力与成本的供给方，不是对手   │
                    └──────────────┬──────────────┘
                                   ↓ 提供能力
                    ┌─────────────────────────────┐
                    │ 直接竞品：同任务、同用户       │
                    │  最常被分析，也最常被高估       │
                    └─────────────────────────────┘
                    ┌─────────────────────────────┐
                    │ 替代方案：用户现在人肉怎么做   │
                    │  最常被忽略，却常常是真对手     │
                    └─────────────────────────────┘
                    ┌─────────────────────────────┐
                    │ 异业进入者：带着既有渠道来的人 │
                    │  从侧面抄近道                 │
                    └─────────────────────────────┘
```

| 层 | 它是谁 | 怎么查（可执行的动作） | 你要拿到的结论 |
| --- | --- | --- | --- |
| **直接竞品** | 面向同一用户、解决同一任务的产品 | 官方定价页、文档、changelog、社区里用户的抱怨帖 | 任务覆盖度、到达路径步数、他们最近三个月改了什么 |
| **替代方案** | 用户今天的土办法：Excel、模板、外包、群里问同事、干脆不做 | 访谈 5–10 个目标用户，问"你上一个替代品是什么""这件事现在谁做、要多久" | 用户当前的成本、频率、以及"不做"的容忍度 |
| **上游** | 模型 API、Agent 平台、向量库、基础设施 | 官方文档与定价页、发布说明 | 你的成本结构、切换难度、供应风险 |
| **异业进入者** | 不在这个赛道，但有渠道和客户关系的公司 | 对方的发布会、财报、招聘 JD、合作公告 | 他们会从哪条路径绕过你的正面战场 |

上游定价页这类信息会变，不要抄进笔记当结论，只记入口：
[OpenAI API 定价](https://openai.com/api/pricing/)（核实于 2026-11）、
[Anthropic 定价](https://www.anthropic.com/pricing)（核实于 2026-11），
**具体数值请以你查询当日的页面为准**。

### 决策表：这一轮该查哪一层

| 你的处境 | 判断依据 | 该怎么做 | 常见错误 |
| --- | --- | --- | --- |
| 产品刚立项，还没有任何真实用户 | 手上没有替代方案样本 | 先去目标行业看现有工具和人工流程，暂不做功能对比 | 拿三家大厂的 AI 功能当竞品，分析了一堆没人买的功能 |
| 已有付费用户，且用户频繁说"XX 也能干" | 用户嘴里出现了替代品名字 | 把替代方案升级为一级竞品，纳入版本跟踪 | 只盯同赛道创业公司，漏掉真正的替代 |
| 产品重度依赖单一模型 API | 该模型调用成本占收入比偏高 | 上游进入风险清单，同时找可替换方案 | 把上游当竞品写了一大段，却没算自己的成本暴露 |
| 面向大客户、有行业准入门槛 | 客户采购清单里有资质项 | 查资质层：哪些资质是硬门槛，拿到就是壁垒 | 把"我们有安全白皮书"当成合规资质壁垒 |

## 3. 竞品拆解框架：能力矩阵（任务 × 能力 × 体验）

官网功能页是**竞品的销售语言**，不是用户语言。从功能页出发做对比，结论一定是"他们功能少"。

正确的起点是**任务**：用户拿它干什么活。从真实任务出发，才知道功能有没有用。

| 轴 | 怎么拆 | 用户能感知到什么 | 怎么测 |
| --- | --- | --- | --- |
| **任务轴** | 用用户原话："帮我把这周工单整理成给客户的周报" | 我想干的事它能不能接住 | 从 10 个真实任务逐个跑 |
| **能力轴** | 0 不支持 / 1 要人补全 / 2 能做但要改 / 3 直接可用 / 4 比人做得好 | 输出能不能直接用 | 对同一任务打分（0–4） |
| **体验轴** | 入口在几步之外、要不要切上下文、等多久、错了怎么恢复 | 顺不顺、敢不敢用 | 记录到达路径步数与失败恢复方式 |

### 打分口径：一次任务级拆解长什么样

对 10 个真实任务（来自访谈或工单），逐个在每个竞品上试一遍，给每个（任务 × 产品）打一个 0–4 分，
同时记下"到达这个能力要几步"：

| 分档 | 判定标准 | 到达步数 |
| --- | --- | --- |
| 0 | 根本不支持这个任务 | — |
| 1 | 支持，但必须人补全才能用 | |
| 2 | 能做出来，但输出要改 | |
| 3 | 输出直接可用 | |
| 4 | 比人做得好 | |

> 表是一张填好的矩阵，行是任务、列是竞品、格子里是「分数 + 步数」。

**产品经理怎么用它**：矩阵不是用来排名谁强谁弱，而是用来**找空白格**——
那些"大家都做到了 3 分，但都要人改"的任务，就是你能做差异化的位置。

**关键动作**：每个任务都要**亲手在竞品上跑一遍**，看官网没用。AI 产品的实际能力和宣传经常不一致，尤其是新发布的功能。

## 4. 市场地图：两轴定坐标（象限示意）

```
                              自动化等级
        高  ┌──────────────────┬──────────────────┐
            │   自动执行层      │   流程托管层      │
   全自动   │  系统自己跑完      │  嵌在系统里执行    │
   执行     │  信任成本最高      │  替换人工流程      │
            ├──────────────────┼──────────────────┤
   半自动   │   通用助手层      │   工作流插件层    │
   草稿     │  人在旁边盯着      │  人在流程中        │
        低  └──────────────────┴──────────────────┘
            低深度              高深度
                    嵌入工作流的深度 →
```

| 象限 | 典型形态 | 竞争烈度 | 胜负关键 | 主要风险 |
| --- | --- | --- | --- | --- |
| **通用助手层** | 独立聊天/网页应用 | 最高，模型厂商与平台人人都有 | 分发与使用习惯 | 一旦平台方做同样的功能即被碾压 |
| **工作流插件层** | 嵌在 IDE、CRM、工单系统里的助手 | 中，需要既有系统合作 | 集成深度与上下文质量 | 系统方自研（你成了被替换的插件） |
| **流程托管层** | 接管一段端到端流程（对账、审核、跟进） | 中低，需要行业 know-how | 责任边界与可回滚 | 出错时责任在谁 |
| **自动执行层** | 无人值守的 Agent | 当前低但正在快速变高 | 可观测、可回滚、可授权 | 信任与合规风险集中爆发 |

**判断标准**：把竞品和自己各画一个点，画不出来的，说明定位还不成立。
如果你在四个象限都画了"我们都能做"，那不是定位，是没有定位。

### 决策表：你的产品该落在哪个象限

| 你的处境 | 判断依据 | 该怎么做 | 常见错误 |
| --- | --- | --- | --- |
| 模型能力是主要卖点，没有独有数据 | 能力轴上你和头部平台打平 | 别在通用助手层正面打，往工作流插件层挪 | 和平台方比谁的模型更便宜 |
| 已有稳定的行业客户和数据 | 客户在某个流程里反复用你 | 往流程托管层走，把人工环节替换掉 | 停在"建议"层，用户还是自己干活，价值没兑现 |
| 目标用户是高风险决策者（法务、财务、医疗） | 出错代价高，责任需要明确 | 先在"人审批"的半自动层建立信任，再谈自动化 | 一上来做全自动，把风险全揽到自己身上 |
| 你的能力只有 API，没有界面 | 没有任何到达路径 | 优先解决分发（见第 5 节），否则模型再强也无人用 | 误把"有 API"当作"有产品" |

## 5. 差异化四问：逐个要证据

四个问题对应第 1 节的四类资产。**每个答案都要附证据**，没有证据的答案就是没有答案。

| 问题 | 判据 | 回答"有"需要拿出什么 | 回答"没有"时往哪补 |
| --- | --- | --- | --- |
| **独有数据** | 别人拿不到、你也拿得起 | 数据来源清单 + 独占/授权/自采的凭据 | 转向"累积性数据"（用得越多越准）或独家渠道数据 |
| **独占工作流位置** | 不用你，这一步就没法做 | 你在哪个系统里、系统方是否离不开你 | 谈系统级合作，把位置换回来 |
| **独有分发** | 你能直达用户 | 三个获客渠道 + 各自成本与规模 | 换一个你天然有关系的垂直人群 |
| **独有合规资质** | 有牌照/认证/私有化能力 | 资质名称、有效期、可覆盖的客户范围 | 从最容易拿到的那个开始（如数据本地化部署） |

**产品经理怎么用它**：这四问的答案直接决定两件事——
价值主张怎么写（见 [06-定位、价值主张与商业模式.md](06-定位、价值主张与商业模式.md)），
以及定价锚点取自用户省下的哪部分成本（同一章）。

**注意反例**：说"我们有大数据"不是答案，"我们持有某类交易流水且该品类三年内无第二家公开采购"才是答案。

## 6. 警惕伪竞品分析：功能表对比的四个失效点

网上流传的竞品分析大多是这个形态：两列功能 + 一堆 ✓/✗。它有四个结构性的失效点。

| 失效点 | 为什么失效 | 修法 |
| --- | --- | --- |
| **静态快照 vs 版本漂移** | AI 产品迭代以周计，表格做完一周就过期 | 每张表标注核实日期与版本；记录"变化信号"而不是一次性结论 |
| **功能有无 vs 任务完成率** | 标了 ✓ 的功能，可能实际做不好或前提条件苛刻 | 换成任务级指标：同一任务的完成质量与所需人工修正量 |
| **忽略到达路径成本** | 同样一个能力，在一个产品里要切 5 次，在另一个里一步可达 | 把"到达路径步数"和"上下文切换次数"计入对比 |
| **把竞品当静态** | 你在对比一个会持续迭代的对手，结论会过期 | 追踪对方的 changelog 与用户抱怨，把结论写成"截至某日的状态 + 变化方向" |

再加一条容易被忽略的：**填表人自带立场**。
每一项后面加一句"这一项我可能判断错了"，逼自己把判断依据摊开。

**替代方案对比用同一套模板**：用户现在用 Excel 做，缺哪些功能、成本多少、能忍多久。

## 7. 案例拆解：三组竞品对照（示意案例）

> 以下为**示意案例**，用于演示分析动作与结论句式，不代表任何一家公司的真实内部数据、定价或性能指标。

### 案例 A：编码助手

| 形态 | 地图坐标 | 任务差异 | 胜负关键 |
| --- | --- | --- | --- |
| 编辑器内补全 | 高深度 / 低自动化 | 补当前文件的几行 | 延迟与"不打断" |
| 终端 Agent | 中深度 / 中自动化 | 跨文件改动、跑测试 | 上下文范围与改动可审阅 |
| 代码托管平台内置审查修复 | 高深度 / 高自动化 | 接到提交流程里 | 与合并、CI 的耦合程度 |

**结论句**：同一句"AI 编码"标签下，差异不在模型强弱，而在**离提交还有多远**。
离提交流程越近，替换成本越高，但出错代价也越大。

### 案例 B：企业知识问答

| 形态 | 知识从哪来 | 答案有无引用 | 出错谁负责 |
| --- | --- | --- | --- |
| 通用聊天 + 上传文档 | 用户手上文件 | 通常没有或很弱 | 用户自己 |
| 接内部系统的问答 | 内部系统实时查询 | 有 | 平台方（需可追责） |
| 嵌在工单系统里的 Copilot | 流程内数据 | 有，且带上下文 | 系统方 |

**结论句**：企业客户买的不是"答得像人"，而是**"答案可信 + 出错能追"**。
所以差异沉淀在数据接入与引用机制上，不在话术上。

### 案例 C：客服 Copilot

| 形态 | 谁承担风险 | 自动化的边界 | 客户感知 |
| --- | --- | --- | --- |
| 给坐席看建议回复 | 坐席 | 生成建议，人选 | 坐席效率提升 |
| 生成回复草稿，一键发送 | 坐席+主管 | 人确认后发出 | 效率与一致 |
| 全自动处理工单 | 公司 | 系统闭环 | 便宜，但投诉风险最高 |

**结论句**：自动化等级每升一级，**责任归属就要重写一次**。
这也解释了为什么行业里实际落地的多是前两档。

## 8. 常见误区清单

- **把"模型更强"当差异化**：模型能力是入场券，半年内会被抹平
- **只分析同赛道创业公司**：用户真正的对手常是人肉流程、Excel 和"不做"
- **拿功能表当结论**：功能有无 ≠ 任务能不能完成
- **抄竞品的功能分类法**：那是人家的销售话术，不是用户的说法
- **竞品表没有时间戳**：三周后就没人知道它说的是哪个版本
- **把"大厂也做了这功能"当需求已被验证**：大厂做的是流量入口功能，不一定是付费场景
- **不看上游**：模型涨价或下架，直接改写你的商业模型
- **地图上什么都能做**：覆盖四个象限不是定位，是没定位

## 9. 交付物：一份可执行的竞品地图

竞品分析不是读完就扔的文档，它应该是一份**带版本基准、可复核**的记录：

| 组成 | 要填什么 |
| --- | --- |
| 版本基准 | 这份分析对应哪个月、哪个版本（如 2026-11）。三周后就没人知道它说的是哪个版本 |
| 我们的坐标 | 嵌入深度 + 自动化等级（第 4 节两轴） |
| 直接竞品 | 每个竞品一行：任务覆盖（用用户原话，不用功能名）、任务完成质量（0–4 口径，见第 3 节）、到达路径步数 |
| 变化信号 | 每个竞品最近三个月的动作——比"现在有什么功能"更能说明它往哪走 |
| 替代方案 | 用户当前的做法，及其单次成本与用户容忍度 |
| 上游依赖 | 用了哪些上游组件、成本占比（价格需自行核实当前值） |
| 差异化四问 | 独有数据 / 独占工作流位置 / 独有分发 / 独有合规资质，每问都要结论 + 证据 |
| 空白格 | 大家都做到 3 分但都要人改的任务——这就是你的差异化位置 |

**三条自查**：
1. 每个结论后面有没有"依据是什么"？
2. 有没有一条是关于"用户今天怎么干"的？
3. 我们的坐标改了吗？如果改了，第 4 节的象限结论要跟着改。

## 10. 本章练习

```bash
cd Demos/examples && uv run --project .. python -m ai_pm_lab week3
```

练习做两件事：

1. **竞品能力矩阵**：给几个竞品（可用你熟悉的产品形态做占位），在 3–5 个真实任务上打分，
   输出"任务 × 能力"矩阵，并标出空白格
2. **市场地图坐标定位**：把竞品和自己标到"嵌入深度 × 自动化等级"两轴图上，
   输出坐标与象限结论

**怎么算做对**：
- 矩阵里的每一格都有评分口径（0–4），而不是"有/没有"
- 地图上每个点都有理由，能说清"为什么落在这一格"
- 至少有一条结论指向**替代方案**（用户现在人肉怎么做），而不全是同赛道产品
- 练习脚本里的竞品数据是占位样例，**换成你自己核实过的信息**再用于决策

## 11. 本章要点

- AI 产品的差异沉淀在**数据、工作流位置、分发、合规资质**，不在模型参数
- 竞品要分**四层**看：直接竞品、替代方案、上游、异业进入者；替代方案最常被漏
- 拆解要从**任务**出发，不是从官网功能页出发；每个任务亲手在竞品上跑一遍
- 能力矩阵三轴：**任务 × 能力 × 体验**；矩阵是用来找空白格的，不是用来排名
- 市场地图两轴：**嵌入工作流的深度 × 自动化等级**；四个象限的胜负条件各不相同
- 差异化四问每问都要有证据，"我们有大数据"不算答案
- 功能表对比有四个失效点：版本漂移、功能有无、到达路径成本、竞品非静态
- 每张竞品表都要带核实日期；具体定价与份额数值请自行核实当前数据

---

## 一句话结论

> **竞品分析不是比功能表，而是找位置**：先分清四层竞品，再用任务级能力矩阵找到"大家都做不到 3 分以上"的空白格，最后用差异化四问确认位置守得住。
