# AI Infra 推理服务教程（18 章 + 毕业作品）

**学什么**：把一个大模型放进生产环境服务，需要算清楚哪些账、盯住哪些指标、
在哪些地方做取舍。这套教程把这些"算账"的方法讲透，并让每一章都能跑出可验证的数字。

**怎么学**：先读笔记，再跑对应实验，跑通了再看下一章。
所有实验离线运行——不联网、不调模型、不需要 GPU、不花 token。

**配套代码**：[`Demos/examples/infra_lab/`](../../Demos/examples/infra_lab/README.md)

---

## 这套课解决什么问题

AI Infra 不是"背架构图"。它的核心是**一组可计算的约束**：

- 显存够不够装下权重和 KV cache？装不下时先牺牲谁？
- decode 阶段为什么慢？因为 GPU 大部分时间在等显存，不是在算。
- 批量开多大？开大了真的更快吗？
- 一次请求到底花多少钱？这个钱花在哪一段？
- 延迟超了，是排队排的还是模型算的？

这套教程把这些问题的答案写成**公式**，再写成**可运行的实验**。
读完你应该能对着任何一张 GPU 规格和任何一个模型 config，
算出"这台机器能跑多少并发、每秒多少 token、每百万 token 多少钱"。

## 16 周排期（约 10 小时/周）

每周节奏固定：**读笔记 3 小时 → 跑实验 3 小时 → 写笔记 3 小时 → 复盘 1 小时**。
"写笔记"不是抄，是用自己的话回答每章的"判断依据"那几段——
说不出来就是没学会。

| 第 3 周 | 05 | 算清你的服务 KV cache 能装多少 token | ★★☆ |
| 第 4 周 | 06 | 用分页模拟算出你的显存浪费率 | ★★☆ |
| 第 5 周 | 07 | 复现"静态批拖死短请求" | ★★★ |
| 第 6 周 | 08 | 用你的真实负载画像跑三种调度策略 | ★★★ |
| 第 7 周 | 09 | 定下你的模型量化方案并说明理由 | ★★☆ |
| 第 8 周 | 10 | 算出投机采样的盈亏平衡接受率 | ★★☆ |
| 第 9 周 | 11 | 设计你的网关限流与路由策略 | ★★☆ |

## 毕业作品

**迷你推理服务**：把第 5、6、7、11、12 章的机制装进一个能跑的服务。

- 分页 KV 缓存（块表 + 引用计数 + 前缀块共享）
- 连续批处理（iteration 级调度，长短请求不互相拖死）
- 前缀缓存（块级链式哈希，命中则跳过已算过的 prefill）
- 前缀亲和路由 + 令牌桶限流
- 完整的 SLO 判定与指标汇总

毕业作品自检不满足于"跑通"，而是**逐条机制去证明它真的在起作用**：
前缀缓存必须真的让 TTFT 下降、亲和路由必须真的把请求钉在同一副本、
限流器必须真的削平突发。

```bash
cd Demos/examples
uv run --project .. python -m infra_lab capstone
```
