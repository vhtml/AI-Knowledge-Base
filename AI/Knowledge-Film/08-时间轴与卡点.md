# 08 · 时间轴与卡点

> **这篇要回答**：没有旁白，节奏靠什么撑？怎么让字幕和音乐咬合上？

---

## 1. 节奏的三个来源

无人声的片子，节奏只有三个来源：

| 来源 | 作用 | 怎么做 |
| --- | --- | --- |
| 字幕切换 | 观众的阅读节奏 | 停留 3–5 秒，句间留呼吸 |
| 画面变化 | 视觉节奏 | 每句只改一处，场景之间长出来而不是硬切 |
| 音乐 | 底层节拍 | 字幕和动作落在拍点上 |

第三个是"顺"的来源。观众说不出为什么，但会觉得这条片子很流畅——
因为他们不需要在"读字"和"看画面"之间抢注意力。

---

## 2. 字幕时间轴

时间轴不是拍脑袋排的，是算出来的：

```
hold = clamp(字数 × 0.22, 1.8, 5.0)   # 没有指定就按字数算
start(n) = end(n-1) + 呼吸间隙          # 呼吸间隙 0.15–0.5 秒
```

**按字数算停留**是这套流程里最省事的一个约定：
写完稿子，时间轴自动就有了，改稿自动重排。

实测样本的区间：

| 指标 | 值 |
| --- | --- |
| 单句停留 | 3.0–3.8 秒 |
| 句间呼吸 | 0.3–0.5 秒 |
| 正文语速 | 4.5–7 字/秒 |
| 最长无字幕纯画面 | 2.0 秒 |

注意时间轴必须**单调不重叠**：后一句的开始时间 ≥ 前一句的结束时间。
这一条可以机器检查，见实验。

---

## 3. 卡点：把字幕吸附到拍点上

配乐有 BPM（每分钟节拍数），拍点间隔是 `60 / BPM` 秒。
120 BPM 就是每 0.5 秒一拍。

把每句字幕的开始时间吸附到最近的拍点：

```python
step = 60.0 / bpm
snapped = round(round(t / step) * step, 3)
```

偏差 ≤ 250ms 就算命中。

**命中率不是越高越好。** 实测样本是 8/8 = 100%，但那是 30 秒的短片。
2–5 分钟的长片通常落在 75%–85%——剩下的 15%–25% 是刻意留的呼吸。
每句都精确咬在拍点上，听起来会像节拍器，反而机械。

### 什么时候该卡，什么时候不该

| 该卡 | 不该卡 |
| --- | --- |
| 关键的揭晓点 | 提问之后的停顿 |
| 场景切换 | 观众正在读的字 |
| 动作发生的那一下 | 纯画面的长镜头 |

## 4. 段落结构和音乐结构对齐

BGM 不是背景音，它有结构：铺垫 →  buildup → 爆发 → 安静 → 再来。

对齐的规矩：

| 音乐段落 | 放什么 |
| --- | --- |
| 铺垫 | 现象、悬念、第一个例子 |
| 爆发 | 核心揭晓（最大的那一下） |
| 安静 | 反转、另一面、留给观众的思考 |

**最大的那次揭晓，要对到音乐重新进入的那一拍。**
这是全片最重要的一个对齐点——错过它，整条片子的高潮就泄了。

反过来，**场景之间是"长出来的"还是"推拉过去的"，不是硬切**。
硬切会让观众觉得跳；从一个场景推拉过渡到另一个，观众会觉得"原来是这样"。

---

## 5. 片名卡的位置

| 规矩 | 值 |
| --- | --- |
| 绝不在第 1 秒 | 第 0 秒是片头，观众还在判断"要不要看" |
| 出现在片长的 5%–30% | 太早打断开场，太晚观众不知道在讲什么 |
| 结尾再出现一次 | 最后一屏是片名 + 文献 |

片名卡是"题目抛出来"，不是"开场介绍"。
它出现的时候，正在讲的那件事**不要停**——画面继续动，字压在上面。

---

## 6. 纯画面段落

每 20–30 秒要有一段没有字幕的纯画面。

为什么需要：字幕是唯一的信息通道，观众一直在读。
读到最后会累，需要一段"什么都不用读、只用看"的喘息。

实测样本里问句之后的那 2 秒就是这种段落——
问号停在屏上不动，观众自己得出答案，然后才轮到那句「不」。

**这 2 秒是整条片子里最值钱的 2 秒。**

## 7. 自查

- [ ] 时间轴单调、不重叠？
- [ ] 每句停留 3–5 秒？句间有呼吸？
- [ ] 字幕起点和拍点的命中率 ≥ 75%？
- [ ] 最大的揭晓对到了音乐重新进入的那一拍？
- [ ] 场景之间是长出来的/推拉过去的，没有硬切？
- [ ] 片名卡在片长的 5%–30%，且不在第 1 秒？
- [ ] 全片至少有一处 2 秒以上的纯画面？
