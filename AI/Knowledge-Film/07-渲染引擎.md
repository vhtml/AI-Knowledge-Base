# 07 · 渲染引擎：画面必须是时间的纯函数

> **这篇要回答**：代码怎么写，才能撑起一条 2–5 分钟的片子？
> 答案只有一句：**画面是时间的纯函数**。

---

## 1. 为什么是代码而不是视频模型

2026 年做这类片子有两条路：

| 路线 | 能做什么 | 做不了什么 |
| --- | --- | --- |
| 视频生成模型（即梦、可灵、Runway…） | 质感好、有真人、有实拍感 | 逐帧不可控；多期之间风格会漂；改一句文案要重抽 |
| **代码渲染（Canvas/JS）** | 逐帧精确、可复现、可局部重渲、能连续做多期 | 画面质感偏"图形"，做不出实拍 |

Vibe 知识这个片型恰好吃代码渲染的长处：
它的画面本来就是**图形和图形的变化**（计数器在数、折线在收敛、细胞在变形），
不是实拍质感。程序画的波、线、柱子，正是这类内容的理想视觉。

而且它有一个别的路线没有的性质：**可复现**。
同一条片子，下周再渲染一次，出来的东西一模一样。
对要连续更新的账号来说，这不是加分项，是生死线。

---

## 2. 三条铁律

### 规矩一：`render(t)` 是纯函数

```javascript
function render(ctx, t) {
  ctx.clearRect(0, 0, W, H);
  drawBackground(ctx, t);
  scene.draw(ctx, t);       // 场景只看自己的那段时间
  drawSubtitle(ctx, t);
}
```

给定 `t`，画出那一帧应该有的**全部**像素。函数内部不读"上一帧画过什么"，
不读全局的累加计数器，不读墙上时钟。

**为什么这条是全部规矩里最硬的**：
播放器可以"接着上一帧画"，逐帧渲染器不行——它手里只有 `t`。
如果画面偷偷依赖了上一帧，逐帧渲染出来的片子就会前后抖：
同一段动画，在浏览器里播放完全正常，导出成视频就一帧一帧地跳。

这种 bug 极难排查，因为**预览永远是对的**。

### 规矩二：不确定性必须被种子固定

要画星点、噪点这类"随机"元素，不能用 `Math.random()`。用带种子的确定性伪随机：

```javascript
function seeded(i) {
  const x = Math.sin(i * 12.9898 + 78.233) * 43758.5453;
  return x - Math.floor(x);
}
const STARS = Array.from({ length: 160 }, (_, i) => ({
  x: seeded(i * 3 + 1),
  y: seeded(i * 3 + 2),
  r: 0.6 + seeded(i * 3 + 3) * 1.4,
}));
```

星点在初始化时算一次就固定下来，第 800 帧和第 1 帧的星点是同一批。
闪烁靠 `Math.sin(t * ...)`，用 `t` 算，所以仍然是纯函数。

### 规矩三：常驻元素画在最外层

```
render()
├── 背景（渐变 + 星点）
├── 场景（只有当前这一段）
├── 片名卡（可选，常驻层的一部分）
├── 暗角
└── 字幕          ← 永远在最上面
```

场景**不许**画字幕，也不许画进字幕区。
这样"字幕区有没有被别的东西占掉"就永远不需要检查——
结构上就不可能发生。

## 3. 一个概念一个函数

不要写一个 800 行的 `render`。拆成场景函数：

```javascript
const SCENES = [
  { t0: 0.0,  t1: 7.8,  name: '乱线', draw: drawNoise },
  { t0: 7.8,  t1: 11.5, name: '拆开', draw: drawSplit },
  { t0: 11.5, t1: 14.7, name: '正弦', draw: drawSines },
  ...
];
```

每个场景函数只拿自己那段时间干活。它的入参是 `t`，
它自己算 `progress = ease((t - t0) / (t1 - t0))`。

好处很直接：
- 改第 3 镜不会碰坏第 5 镜；
- 场景之间首尾相接可以**机器校验**（第 7 章的实验会查）；
- 长片可以按章拆文件，几百行一个文件永远没人敢动。

## 4. 渲染页：只做一件事

```html
<canvas id="stage"></canvas>
<script src="film.js"></script>
<script>
  const t = parseFloat(new URLSearchParams(location.search).get('t') || '0');
  const ctx = document.getElementById('stage').getContext('2d');
  seek(ctx, t);
</script>
```

渲染页**只**把 URL 上的 `t` 交给 `seek(t)`。
"预览看到的"和"渲出来的"因此一定一致——它们走同一条代码路径。

这个页面同时是预览页、联络表的来源、逐帧渲染的入口。
一套代码，不维护两份。

## 5. 怎么检查"确实是纯函数"

### 静态检查

扫一遍代码（**去掉注释**），找不确定性来源：
`Math.random`、`Date.now`、`performance.now`、`new Date`。

注释里写"不要用 `Math.random`"是正常的说明文字，不该被当成违规——
所以扫描前必须先剥掉注释。

### 动态检查

同一个 `t` 渲两遍，**逐字节**比对 PNG：

```bash
python -m vibe_film_lab.engine.render <工程目录> --det
```

这两帧必须完全一样。哪怕差一个像素——一个抗锯齿的抖动、
一个浮点累加的误差——都会被抓出来。

这条检查是整条流水线的地基。没有它，逐帧导出出来的片子就是不可信的。

---

## 6. 纯函数换来的是什么

| 能力 | 为什么纯函数是前提 |
| --- | --- |
| 逐帧渲染 | 渲染器只有 `t`，没有"上一帧" |
| 局部重渲 | 渲第 40–43 秒不用重渲全片，结果和全渲一致 |
| 静态复核 | 同一时刻的静帧永远一样，可以拿来做对比图 |
| 并行 | 帧之间没有依赖，4 路并行和 1 路结果逐字节相同 |
| 版本对比 | 改完代码重渲，差异图能精确定位到帧 |

这些能力加起来，才让"一个人一周做几条"成为可能。

## 7. 自查

- [ ] `render(t)` 里没有任何跨帧状态？
- [ ] 代码里没有 `Math.random` / `Date.now`？
- [ ] 随机元素用了带种子的伪随机？
- [ ] 场景表首尾相接，铺满全片？
- [ ] 场景函数各自独立，没有共享的累加变量？
- [ ] 字幕和常驻元素在最外层？
- [ ] `--det` 跑过了？

---

**一句话**：`render(t)` 是纯函数，不是播放器。
播放器可以"接着上一帧画"，逐帧渲染器不行——它只有 `t`。
从第一天就按纯函数写，比渲完再改便宜一百倍。
