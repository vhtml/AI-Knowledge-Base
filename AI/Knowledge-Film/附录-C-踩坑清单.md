# 附录-C · 踩坑清单

按"症状 → 原因 → 处理"编排。每条都是实际做一条片子时会撞上的。

---

## C1 · 截出来是白图

**症状**：`--screenshot` 出来的 PNG 全白，什么都没有。

**原因**：页面里的 JS 还没跑完，截图就先发生了。Canvas 是脚本画的，
脚本没执行就没有内容。

**处理**：等页面加载完再截。本教程的渲染管线用 ego lite 驱动，
每帧的顺序是：导航到 `?t=…` → 等 `load` 状态 → 截图。

```js
await page.goto(url);
await page.waitForLoadState("load");
await page.screenshot({ path });
```

**不要**因此去怀疑 Canvas 画错了——先查这一步。

---

## C2 · 并发渲染时某一帧没生成

**症状**：`--jobs 4` 跑着跑着报截图失败，某一帧没生成。

**原因**：浏览器偶尔会在截图那一刻无响应（`EGO_PAGE_UNRESPONSIVE`）。
页面本身可能还是好的——`page.evaluate()` 照样能跑——只是这一次没截出来。

**处理**：两样东西。

1. **单帧失败重试一次**：偶发失败不该让整条片子前功尽弃。
   渲染脚本对每帧的截图都包了一层重试。
2. **每个渲染任务开一个独立的浏览器空间**：同名空间是复用的，
   两个渲染并发跑时后者会把前者的空间关掉，前者就报"空间不存在"了。

真遇到了还能**续渲**：帧号连续的目录里，只补缺的那几帧就行，不用从头再来。

```bash
python -m vibe_film_lab.engine.render <工程> --frames 756 758
```

> 这条不是理论：写这份教程时，一条 903 帧的片子渲到最后一帧，
> 正好有一帧没截出来。用上面的重试 + 续渲补齐，没有重头再渲一遍。

## C3 · 静态检查把注释里的关键字当成违规

**症状**：检查"不许出现 `Math.random`"时，明明只在注释里写了一句
"不要用 Math.random"，检查器还是报错。

**原因**：扫描的是整个文件，没剥注释。

**处理**：扫描前先去掉注释。注释里写禁令是正常的说明文字。

```python
source = re.sub(r"/\*.*?\*/", "", source, flags=re.S)
source = re.sub(r"//[^\n]*", "", source)
```

（这是简写实现，不处理字符串里的 `//`。要严格就得用真正的 JS 解析器。）

## C4 · 画面在预览里正常，导出后前后抖

**症状**：浏览器里播放很顺，导出的 MP4 同一段动画一帧一帧跳。

**原因**：画面里藏了跨帧状态——累加的计数器、没播种的 `Math.random`、
依赖上一帧的插值。播放器和逐帧渲染器的区别就在这里：
播放器手里有"上一帧"，渲染器只有 `t`。

**处理**：把 `render(t)` 写成纯函数；随机元素用带种子的伪随机；
最后用 `--det`（同一 `t` 渲两遍逐字节比对）当作门禁。

**这类 bug 预览永远是对的**，所以必须靠机器检查，不能靠眼看。

## C5 · 字幕和画面对不上

**症状**：写完文案开始画，发现第 3 句字幕说的是"拆开"，画面画的还是乱线。

**原因**：文案和分镜是分两次写的，时间轴没对齐。

**处理**：**文案和分镜表一起写**，一行一句，一行一镜。
写完立刻用脚本核对 `film.js` 里的 `SUBS` 和文案稿是否逐字一致。

这不是流程洁癖：长片有 40 句字幕，手改一定会漏，
而漏一句的表现是"某句字幕没有对应的画面"——观众不会报错，但会觉得怪。

---

## C6 · 染色把整句都染了

**症状**：想给一个关键词染色，结果整句话变成金色。

**原因**：标记的语义没定清楚，"标记后面是关键词"还是"标记前面是关键词"？

**处理**：定死一条规则并写进文档：**标记染它前面那一段**
（从上一个句读起，到标记为止的那段）。写实现的时候按这条规则切句读。

---

## C7 · 语速统计莫名偏低

**症状**：样片的语速只有 4.4 字/秒，明明每句都不长。

**原因**：把结尾的片名卡算进去了。片名卡字少（14 字）停留长（3 秒），
一句就把平均值拉下来了。

**处理**：语速按**正文句**算，片名卡单独算。
同理，片名卡的停留要求是"不短于 3 秒"，而不是"落在 3–5 秒"。

---

## C8 · 事实检查误报"数字没上屏"

**症状**：事实表里有一条"正弦波叠加定理"（不上屏，只在片尾讲），
检查器报"这个数值没有出现在字幕里"。

**原因**：事实表没有区分"要上屏的事实"和"只作背景的事实"。

**处理**：给事实表加一列 `上屏？`。不上屏的事实不参与"必须出现在字幕里"的检查，
但它必须留在表里——片尾要印文献，讲解时要能追溯。

---

## C9 · 全片没有一处留白

**症状**：30 秒的片子从头到尾字幕没停过，看完有点喘不上气。

**原因**：把每句字幕都排得严丝合缝，"该停的停"没做。

**处理**：每 20–30 秒留一段无字幕纯画面。
问句之后尤其要停——实测样本里问句后停 2 秒，问号挂在屏上，
然后才给出答案那句"不"。这 2 秒是全片最值钱的 2 秒。

---

## C10 · 并行不一定更快

**症状**：以为 `--jobs 4` 一定快 4 倍，实测只有 0.9 倍。

**原因**：渲染器本身会开多个渲染线程，机器核少时并行只是在抢核。
每一帧的固定成本是**一次导航 + 一次截图**，这部分可以摊薄，
但抢核那部分摊不掉。

**处理**：**实测，不要假设**。在实验室里跑 1 路 vs 4 路，报出加速比。

要真正提速，上"复用浏览器 + 多页并行"：
起一个浏览器、开几个页面，每个页面逐帧 `seek(t)` + 截图。代价是多一个依赖。

建议顺序：先把复用浏览器的实现跑通，再按实测决定路数。

## C11 · 片子在手机上黑屏

**症状**：本地播放器好好的，上传后有些平台显示黑屏或花屏。

**原因**：用了 `yuv444p` 或 10bit 编码。平台的转码器只吃 `yuv420p` 8bit。

**处理**：固定 `-pix_fmt yuv420p`，别为了画质折腾色彩深度——
观众根本看不出 8bit 和 10bit 的区别，但平台兼容性是硬约束。

---

## C12 · 浏览器里预览没有声音

**症状**：用 `file://` 打开页面，画面正常但没声音。

**原因**：浏览器的安全策略禁止 `file://` 页面读取本地音频文件。

**处理**：用本地服务器打开。

```bash
python -m http.server 8737
# 或渲染脚本的 --serve
```

---

## C13 · 改完文案，片子的时长对不上

**症状**：改了字幕字数，但 `CONFIG.DUR` 没改，末尾几秒被切掉或者多出一段黑屏。

**原因**：`DUR` 和字幕时间轴是两处独立维护的数字。

**处理**：把场景表和字幕表都当成真相来源，加一条机器检查：
**场景必须首尾相接铺满 `[0, DUR]`**，且最后一段的结束时间必须等于 `DUR`。

---

## C14 · 片名卡出现得太早

**症状**：第 1 秒就打出片名，观众还没反应过来就走了。

**原因**：把"片名"理解成"开场介绍"。

**处理**：片名卡是"题目抛出来"，不是"开场介绍"。
出现在片长的 5%–30% 之间，而且**正在讲的那件事不要停**——
画面继续动，字压在上面。

---

## C15 · 交了片，但没说清哪些没验过

**症状**：发布后被观众指出"第 23 秒那根线穿过了字幕区"。

**原因**：自动化检查覆盖不到画面细节，而你默认"应该没问题"。

**处理**：交片时把没做到的地方直说，包括"成片我有没有从头到尾看过一遍"。

```
已过：八道门槛的自动项全部通过
人工项：已静音遮字幕看过一遍；已只读字幕读过一遍
未验：成片没有在手机上完整看过一遍；BGM 版权只覆盖站内使用
```

---

## C16 · 素材结构不对，脚本读不出来

**症状**：`'str' object has no attribute 'get'`。

**原因**：`storyboard.json` 有时写成数组、有时写成 `{"shots": [...]}`，
读取脚本只认一种。

**处理**：读取函数两种都认（`if isinstance(raw, dict): raw = raw.get("shots", [])`）。
带说明文字的那个结构更好维护，值得支持。
