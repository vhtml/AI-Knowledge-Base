# LLM 地基 · 八章系统教程

这个目录回答一个问题：**模型 API 到底怎么被调用，每一个旋钮背后是什么，以及出了问题你该查哪一层。**

配套实验在 [`Demos/examples/llm_lab/`](../../Demos/examples/llm_lab/)，一章一篇笔记、一个能跑的实验，
最后产出一个**贴着协议写、换模型零改动**的模型调用层。

> **这套教程刻意贴着协议写**，不引入 LangChain / LangGraph。
> 因为 Agent 开发里 80% 的"玄学问题"——模型不调工具、JSON 解析失败、流式拼接出乱码、
> 成本突然翻倍——根子都在这一层。看懂协议层，这些问题就都不神秘了。

---

## 这套教程的前提假设

- 目标读者：会写 Python，用过 `openai` SDK，但没系统看过模型 API 的协议细节
- 目标产物：**一个可靠的模型调用层**——消息协议清楚、旋钮用对、错误分类明确、成本可估算
- 时间投入：每章 1–2 小时；也可以当长期手册按需查阅
- 语言基线：Python 3.13，只用标准库 + `openai` SDK

## 怎么跑实验

```bash
cd Demos/examples

# 跑某一章
uv run --project .. python -m llm_lab ch03

# 跑全部八章
uv run --project .. python -m llm_lab all

# 自检（验证笔记与实验一一对应，且断言都还成立）
uv run --project .. python -m llm_lab selftest

# 列出所有章节
uv run --project .. python -m llm_lab list
```

### 两条运行路径

| 路径 | 触发方式 | 模型来源 | 用途 |
| --- | --- | --- | --- |
| 确定性路径 | 默认 | 脚本化假客户端 | 学习与回归，断言严格、结果可复现 |
| 真实路径 | `--live` | `Demos/.env` 里的 OpenAI 兼容端点 | 看真模型怎么跑，断言只校验形状 |

```bash
uv run --project .. python -m llm_lab ch03 --live
uv run --project .. python -m llm_lab live
```

真实路径读 `Demos/.env` 的 `LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL`（仓库既有约定）。

## 毕业标准

走完八章，你应当满足全部条件：

- [ ] 能默画四种 role 的消息形状，并说出两条硬约束
- [ ] 知道 `finish_reason` 的每个值分别意味着什么、该怎么处理
- [ ] 能区分"该退避重试"和"该改请求"的四类错误
- [ ] 知道工具调用为什么必须回填 `tool_call_id`
- [ ] 知道结构化输出要校验，校验失败要重试而不是硬解
- [ ] 能正确拼接流式分片，且知道工具调用的流式是另一套形状
- [ ] 能估出一次调用的成本，并说出输入输出比为什么那么悬殊
- [ ] 换模型时知道要重跑哪些评测

## 一句话结论

> **模型 API 不是"一个能聊天的函数"，是一份有硬约束的消息协议加八个旋钮。**
> 把 `system` 的位置、`tool_call_id` 的作用、`finish_reason` 的含义、
> 错误的四分类这四件事记牢，Agent 层的大多数"玄学故障"当场就能定位。
